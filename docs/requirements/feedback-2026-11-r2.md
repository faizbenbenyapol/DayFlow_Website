## 1. ปัญหาและเป้าหมาย
- ปัญหาจากมุมผู้ใช้: เจ้าของลองใช้แอปบน Docker แล้วเจอ 5 เรื่อง: กล่องยืนยันหน้าตาเป็นของสำเร็จรูป, รายการที่บันทึกไว้เป็นสีเทาเกือบหมดจนอ่านยาก, ข้อความเด้งดูไม่เข้าธีม, คนดูลิงก์แชร์ที่ติดตั้งลงมือถือกดย้อนกลับแล้วไม่ออกจากแอป และเปิดไอคอนอีกครั้งไม่กลับมาที่หน้าแชร์, รายการซื้อขายหุ้นปนกันจนดูไม่ออกว่าซื้อไปเท่าไหร่ ขายได้กำไรเท่าไหร่
- เสร็จแล้วใครได้อะไร: เจ้าของและทุกคนที่ใช้ DayFlow ได้หน้าจอที่อ่านง่ายและเข้าธีม v3 ทุกจุด, คนดูลิงก์แชร์ได้ไอคอนบนมือถือที่ทำตัวเหมือนแอปจริง, นักลงทุนเห็นซื้อกับขายแยกกันพร้อมกำไรต่อครั้งที่ขาย
- วัดความสำเร็จยังไง: ไม่มีโค้ดหรือ CSS ของ SweetAlert เหลือในแอป, ไม่มี `alert()`/`confirm()`/`prompt()` ของเบราว์เซอร์, จำนวนเงินในทุกรายการผ่านเกณฑ์ contrast 4.5:1 และมีสีตามความหมาย

## 3. User stories
1. ในฐานะผู้ใช้ ฉันอยากให้กล่องยืนยันและข้อความแจ้งผลหน้าตาเป็น DayFlow เพื่อให้แอปดูเป็นชิ้นเดียวกัน
2. ในฐานะผู้ใช้ ฉันอยากเห็นรายรับเป็นสีหนึ่งและรายจ่ายเป็นอีกสีหนึ่ง ชื่อรายการเด่นกว่าป้ายหมวด เพื่ออ่านรายการย้อนหลังได้เร็ว
3. ในฐานะคนดูลิงก์แชร์ ฉันอยากติดตั้งหน้าแชร์เป็นไอคอนบนมือถือที่เปิดมาเจอหน้าแชร์เสมอ เพื่อไม่ต้องหาลิงก์ใหม่ทุกครั้ง
4. ในฐานะนักลงทุน ฉันอยากดูรายการซื้อกับรายการขายแยกกัน และบอกได้ว่าเงินจากการขายนำไปลงทุนต่อหรือถอนออก เพื่อรู้ว่าเงินไปอยู่ไหน

## 6. ข้อมูลและกฎธุรกิจ
- กำไรขายใช้วิธีต้นทุนเฉลี่ย (average cost) แบบเดียวกับที่ระบบใช้อยู่ ค่าธรรมเนียมซื้อรวมในต้นทุน ค่าธรรมเนียมขายหักจากกำไร
- กำไรที่นำกลับไปลงทุนต่อไม่ใช่เงินต้น: เงินต้นสะสม = ฝาก − ถอน เท่านั้น (ผู้ใช้ยืนยัน 2026-11-23)
- ยอดเงินแยกตามสกุลเงินของรายการ ไม่แปลงสกุล ปัดแสดงผล 2 ตำแหน่ง คำนวณจากค่าเต็มในฐานข้อมูล
- ลิงก์แชร์: ใช้ token เดิมของลิงก์ ไม่สร้าง token ใหม่ ไอคอนที่ติดตั้งเก็บ token ไว้ในที่อยู่เริ่มต้นของแอป (start URL) จึงไม่พึ่ง cookie

## 7. รีไควร์เมนต์ไม่ใช่ฟังก์ชัน (non-functional)
- ไม่มีไลบรารีภายนอกสำหรับกล่องและข้อความแจ้ง หน้าแรกเบาลงเพราะไม่ต้องโหลด SweetAlert (~90KB) อีก
- รองรับโหมดสว่าง/มืด และสีโต๊ะทุกสี, จอ 360px ถึงเดสก์ท็อป, Chrome/Edge/Safari/Firefox ปัจจุบัน
- การเข้าถึง: ตาม REQ-3 และ contrast ≥ 4.5:1 (ตรวจด้วย `scripts/check-contrast.mjs`)
- ความเข้ากันได้: migration ใหม่รันซ้ำได้และไม่แตะข้อมูลเดิม โค้ดบน branch เก่าที่ใช้ฐานข้อมูลเดียวกันไม่พัง

- flow หลัก: กดปุ่มอันตราย → กล่องยืนยันแบบแผ่นการ์ดกระดาษกลางจอ (มือถือ: แผ่นล่างจอ) → ยืนยัน/ยกเลิก → ข้อความแจ้งแบบกระดาษโน้ตที่มุมล่าง
- หน้าจอและสถานะที่ต้องมี: กล่องยืนยันธรรมดา, กล่องยืนยันอันตราย, กล่องถามข้อความ (พร้อมข้อความผิดพลาดใต้ช่อง), กล่องแจ้งผล; ข้อความแจ้ง 4 ชนิด; รายการซื้อ/ขายตอนว่างและตอนมีข้อมูล

## 12. สมมติฐานที่ใช้
- รายการขายแสดงเป็นแท็บย่อย "ซื้อ" / "ขาย" ในแท็บ "ซื้อขาย" เดิม — ถ้าผิด (อยากได้สองตารางวางคู่กัน) แก้แค่ layout
- ยอดถอนตั้งต้น = จำนวน × ราคาขาย − ค่าธรรมเนียม ในสกุลเงินของรายการขาย แก้ได้ก่อนบันทึก — ถ้าผิด แค่เปลี่ยนค่าตั้งต้น
- ข้อความแจ้งอยู่ได้ 3.5 วินาที (ผิดพลาด 6 วินาที) และปิดเองได้ — ปรับเลขได้ง่าย
- สีรายจ่ายในรายการเป็นสีแดงของธีม (`--stamp-red`) ตามที่ token ระบุไว้ว่าใช้กับรายจ่าย — ถ้าอยากให้รายจ่ายเป็นสีหมึกและเด่นเฉพาะรายรับ แก้ที่เดียว

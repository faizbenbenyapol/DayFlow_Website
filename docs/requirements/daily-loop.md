# รีไควร์เมนต์: วงจรใช้งานประจำวัน (Daily Loop)

สถานะ: ยืนยันแล้ว (2026-11-18)
ระดับงาน: เต็ม (ย้ายข้อมูลจริงของผู้ใช้ที่สมัครเข้ามา, เปลี่ยนโครงฐานข้อมูล, แตะหลายโมดูล)   ·   playbook: large-task + feature

## 1. ปัญหาและเป้าหมาย

- **ปัญหาจากมุมผู้ใช้:** DayFlow มีฟีเจอร์เยอะและหน้าตาสวย แต่ใช้จริงทุกวันแล้วไม่คุ้ม เพราะ "สิ่งที่ต้องทำ" แยกอยู่ 4 ที่ (Tasks, to-do รายวันใน Planner, จดด่วน, งานในโปรเจกต์) ทุกครั้งที่นึกงานได้ต้องเลือกก่อนว่าจะจดที่ไหน หน้า "วันนี้" เห็นแค่งานจาก Tasks และ to-do ที่ทำไม่เสร็จก็ค้างอยู่ในวันเก่าโดยไม่มีใครเห็น
- **เสร็จแล้วใครได้อะไร:** ผู้ใช้ทุกคนมีที่เก็บงานที่เดียว จดได้จากทุกหน้า เปิดหน้า "วันนี้" ตอนไหนก็เห็นทุกอย่างที่ต้องทำ งานค้างไม่หาย และกดเริ่มโฟกัสจากงานได้ทันที ส่วนผู้ใช้ใหม่รู้ทันทีว่าควรเริ่มจากตรงไหน
- **วัดความสำเร็จยังไง:**
  - หลังย้ายข้อมูล จำนวนแถวต้นทางเท่ากับจำนวนงานที่ย้ายเข้ามา ไม่มีแถวไหนหาย (ดูจากรายงานของสคริปต์ย้าย)
  - งานทุกชิ้นที่ครบกำหนดวันนี้หรือเลยกำหนด จากทุกแหล่ง ขึ้นในหน้า "วันนี้" ครบ 100%
  - จดงานใหม่จากหน้าใดก็ได้ ใช้ไม่เกิน 1 คลิก/คีย์ลัด + พิมพ์ + Enter

**ไม่มีพิธีประจำวัน** (ผู้ใช้ยืนยัน): ระบบต้องใช้งานได้ดีไม่ว่าจะเปิดเช้า เย็น หรือหายไปหลายวัน จะไม่มีขั้นตอน "ปิดวัน" ที่ต้องทำทุกเย็น

## 3. User stories

1. ในฐานะผู้ใช้ ฉันอยากจดงานจากหน้าไหนก็ได้โดยไม่ต้องคิดว่าจะเก็บไว้ที่ไหน เพื่อจะได้ไม่ลืม
2. ในฐานะผู้ใช้ ฉันอยากเปิดหน้า "วันนี้" แล้วเห็นงานค้าง งานวันนี้ งานโปรเจกต์ที่มอบให้ฉัน และกำหนดการ ในที่เดียว เพื่อตัดสินใจได้ว่าตอนนี้จะทำอะไร
3. ในฐานะผู้ใช้ที่หายไปหลายวัน ฉันอยากจัดการงานค้างทั้งกองได้ในครั้งเดียว เพื่อไม่ต้องกดทีละงาน
4. ในฐานะผู้ใช้ ฉันอยากกดเริ่มจับเวลาโฟกัสจากงานที่เลือก เพื่อให้รู้ว่าเวลาโฟกัสไปลงกับงานไหน
5. ในฐานะหัวหน้าโปรเจกต์ ฉันอยากมอบงานให้สมาชิกตามบัญชีจริง เพื่อให้งานไปขึ้นในหน้า "วันนี้" ของคนนั้น
6. ในฐานะผู้ใช้ใหม่ ฉันอยากรู้ว่าควรเริ่มทำอะไรเป็นอย่างแรก

## 6. ข้อมูลและกฎธุรกิจ

- **"วันนี้"** ใช้วันตามเขตเวลาเซิร์ฟเวอร์ (`TIMEZONE`) เหมือนหน้าอื่นทั้งหมดในตอนนี้
- **ค้าง** = งานยังไม่เสร็จ และวันกำหนด < วันนี้ งานที่ไม่มีวันกำหนดไม่ใช่งานค้าง
- **ยังไม่จัด** = งานที่ยังไม่มีช่องความสำคัญ (Eisenhower) จะมีวันกำหนดหรือไม่ก็ได้
- **งานโปรเจกต์ที่เป็นของฉัน** = ผู้รับผิดชอบผูกกับบัญชีฉัน และฉันยังเป็นสมาชิกของโปรเจกต์นั้น
- **สิทธิ์:** ทุก API ที่เพิ่มต้องตรวจว่าเป็นงานของผู้ใช้ที่ล็อกอิน หรือผู้ใช้มีสิทธิ์แก้ไขในโปรเจกต์นั้น ตรวจที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม
- **ข้อมูลส่วนบุคคล:** ไม่มีข้อมูลประเภทใหม่ รายงานของสคริปต์ย้ายแสดงแค่จำนวน ไม่แสดงเนื้อหางานหรืออีเมลผู้ใช้

## 7. รีไควร์เมนต์ไม่ใช่ฟังก์ชัน (non-functional)

- **ความเร็ว:** จำนวน query ของหน้า "วันนี้" คงที่ ไม่โตตามจำนวนงานหรือโปรเจกต์ (ห้าม query ใน loop) และไม่ช้ากว่าเดิมอย่างเห็นได้
- **ความปลอดภัย:** endpoint ใหม่ใช้ CSRF และการตรวจสิทธิ์แบบเดียวกับของเดิม
- **การเข้าถึง:** ช่องจดเปิด/ปิดด้วยคีย์บอร์ดได้ (Esc ปิด) ปุ่มทุกปุ่มมีชื่อให้โปรแกรมอ่านหน้าจอ
- **ภาษา:** ข้อความใหม่ทั้งหมดเป็นภาษาไทย
- **อุปกรณ์:** มือถือ 375px ขึ้นไป และเดสก์ท็อป ใช้งานใน PWA ได้
- **ความเข้ากันได้:** URL เดิมของ Planner และจดด่วนยังเปิดได้ ไฟล์สำรองเก่า import ได้

## 8. UX/UI

- **flow หลัก:**
  1. นึกงานได้ → กดปุ่มจด/คีย์ลัด → พิมพ์ → Enter → จดต่อหรือปิด
  2. เปิดหน้า "วันนี้" → (ถ้ามี) จัดการกลุ่ม "ค้าง" → ดูงานวันนี้ งานโปรเจกต์ของฉัน กำหนดการ → กดโฟกัสที่งาน
  3. ว่างเมื่อไร → เปิด Tasks → เคลียร์กล่อง "ยังไม่จัด" ด้วยการใส่ช่องความสำคัญหรือวันกำหนด
- **หน้าจอและสถานะที่ต้องมี:** หน้า "วันนี้" (ปกติ / ไม่มีงานเลย / ผู้ใช้ใหม่ / งานค้างเยอะ / โหลดพลาด), ช่องจด (ว่าง / กำลังบันทึก / บันทึกแล้ว / ผิดพลาด), กล่อง "ยังไม่จัด" ในหน้า Tasks, ตัวเลือกผู้รับผิดชอบในงานโปรเจกต์, ตัวเลือกงานในหน้า Focus
- **design plan:** ใช้ระบบดีไซน์ v3 เดิม ("สมุดโทนอ่อน", tokens ใน `tokens.css`, ฟอนต์ Anuphan/Mali) ไม่สร้างสไตล์ใหม่ ก่อนลงมือส่วนหน้าจอจะทำร่างให้ดูก่อน
- **ภาพอ้างอิงที่ผู้ใช้อนุมัติ:**
  - กล่อง "ยังไม่จัด" (ขั้น 3, อนุมัติ 2026-11-19): แถบเต็มความกว้างเหนือ 4 ช่องของหน้า Tasks กรอบเส้นประเหมือนกระดาษโน้ตที่ยังไม่เข้าแฟ้ม แสดง 8 งานแรก (ยังไม่เสร็จก่อน) แล้วปุ่ม "แสดงอีก N งาน" ลากเข้าออกกับ 4 ช่องได้ ว่างแล้วหดเหลือบรรทัดเดียวกับช่องจด บนมือถืออยู่บนสุด ผลค้นหาพาไปที่งานแล้วไฮไลต์

## 9. ข้อจำกัด

- PHP แบบ MVC เดิม ไม่มี Composer, MariaDB, migration ผ่าน `scripts/migrate.php`
- CSS ผ่านด่าน `check-css.mjs` (ห้ามสี hex นอก tokens) และ PHPStan ระดับ 6
- ทดสอบบน Docker ในเครื่องที่ `localhost:8080` เท่านั้น
- **ลงมือเขียนโค้ดโดย OpenCode** ตามเวิร์กโฟลว์ของผู้ใช้ Claude วางแผน เขียน brief และตรวจผลเอง
- **deploy เป็นงานของผู้ใช้** งานนี้ส่งมอบสคริปต์และคู่มือขั้นตอน deploy ไม่รันบน production เอง

## 12. สมมติฐานที่ใช้

- ผู้ใช้ให้ "ตัดสินใจเองได้" กับเรื่องที่เหลือหลังถาม 2 รอบ — ถ้าผิดจะกระทบ: ข้อในหัวข้อ 11 และ 12 อาจต้องเปลี่ยนผ่านคำขอเปลี่ยน
- to-do และจดด่วนที่ย้ายมา ไม่มีช่องความสำคัญ จึงอยู่ใน "ยังไม่จัด" — ถ้าผิดจะกระทบ: กล่อง "ยังไม่จัด" จะมีงานเยอะหลังอัปเดต
- งานใหม่จากช่องจดเข้าท้ายรายการเสมอ — ถ้าผิดจะกระทบ: แค่ลำดับการแสดง แก้ง่าย
- ตารางเดิมเก็บไว้แบบเปลี่ยนชื่ออย่างน้อยหนึ่งรอบ release — ถ้าผิดจะกระทบ: ใช้พื้นที่ฐานข้อมูลเพิ่มเล็กน้อย
- ผู้ใช้ deploy เองและสำรองฐานข้อมูลก่อนรันสคริปต์ย้ายบน production (คู่มือส่งมอบจะเขียนขั้นตอนให้) — ถ้าผิดจะกระทบ: ถ้ามีปัญหาจะถอยได้แค่ด้วยสคริปต์ถอยกลับ
- หน้า Tasks เดิมยังเป็นหน้าหลักของการจัดงาน เพิ่มแค่กล่อง "ยังไม่จัด" ไม่ออกแบบหน้าใหม่ — ถ้าผิดจะกระทบ: ขอบเขตหน้าจอโตขึ้นมาก

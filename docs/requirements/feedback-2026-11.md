# รีไควร์เมนต์: คำขอจากการใช้งานจริง รอบพฤศจิกายน 2569

สถานะ: ยืนยันแล้ว (2026-11-20)
ระดับงาน: กลาง (เฟส 1–3, 5) · เต็ม (เฟส 4 Google Drive: OAuth และย้ายไฟล์จริงของผู้ใช้)   ·   playbook: large-task + kickoff

## 1. ปัญหาและเป้าหมาย

- **ปัญหาจากมุมผู้ใช้:** ใช้ DayFlow จริงแล้วเจอจุดกวนใจเล็ก ๆ (เมนูซ้ำ ป๊อปอัพทุกครั้งที่ติ๊ก ทศนิยมรก หน้าสั่นตอนเปลี่ยนเมนู กราฟดูเหมือนค่าเริ่มต้น) และอยากได้ความสามารถที่ยังไม่มี: เก็บไฟล์ใน Google Drive ของตัวเอง ส่งไฟล์ใหญ่ ปรับเมนูได้อิสระ รู้ว่าแอปอัปเดตอะไร ติดตั้งเป็นแอป และสั่งงานผ่าน AI
- **เสร็จแล้วใครได้อะไร:** ผู้ใช้ทุกคนได้แอปที่นิ่งขึ้นและปรับให้เข้ากับตัวเองได้ เจ้าของระบบไม่ต้องเก็บไฟล์ผู้ใช้บนเซิร์ฟเวอร์เมื่อผู้ใช้เชื่อม Drive
- **วัดความสำเร็จยังไง:** ทุก REQ ในหัวข้อ 4 ผ่านเกณฑ์ยอมรับบนเบราว์เซอร์จริงที่ http://localhost:8080 และ test ชุดเต็มผ่าน

## 2. ผู้ใช้และสถานการณ์ใช้งาน

| ผู้ใช้ | ใช้ตอนไหน บนอุปกรณ์อะไร | สิ่งที่อยากทำให้สำเร็จ |
| --- | --- | --- |
| เจ้าของระบบ | ทุกวัน มือถือ (PWA) และคอม | ใช้งานลื่น ปรับเมนูตามที่ใช้จริง |
| ผู้ใช้ทั่วไปที่สมัครเข้ามา | ไม่แน่นอน | ใช้แค่เมนูที่ตัวเองต้องการ ไม่ต้องอ่านศัพท์นักพัฒนา |
| ผู้รับไฟล์ | ไม่มีบัญชี DayFlow | ใส่รหัสแล้วได้ไฟล์ ข้อความ หรือลิงก์ |

## 3. User stories

1. ในฐานะผู้ใช้ ฉันอยากติ๊กงานหรือนิสัยแล้วเห็นแค่เครื่องหมายถูก ไม่มีป๊อปอัพเด้งทุกครั้ง
2. ในฐานะผู้ใช้ ฉันอยากซ่อน ย้าย และเปลี่ยนชื่อหมวดเมนูได้เอง เพราะฉันใช้ไม่ครบทุกเมนู
3. ในฐานะผู้ใช้ ฉันอยากรู้ว่าแอปเวอร์ชันไหนเปลี่ยนอะไร ด้วยภาษาที่คนทั่วไปอ่านเข้าใจ
4. ในฐานะผู้ใช้ ฉันอยากกดติดตั้ง DayFlow ลงมือถือหรือคอมจากหน้าตั้งค่า
5. ในฐานะผู้ส่ง ฉันอยากส่งไฟล์กี่ไฟล์ก็ได้ ประเภทไหนก็ได้ รวมไม่เกิน 10 GB หรือส่งแค่ข้อความ/ลิงก์ก็ได้
6. ในฐานะผู้ใช้ ฉันอยากให้ไฟล์ของฉันอยู่ใน Google Drive ของฉัน แต่จัดการทั้งหมดผ่านเมนูไฟล์ของ DayFlow
7. ในฐานะผู้ใช้ ฉันอยากดูว่าปีนี้จ่ายไปกับหมวดไหนมากสุด และรายการไหนก้อนใหญ่สุด
8. ในฐานะผู้ใช้ ฉันอยากพิมพ์สั่ง AI ให้จดงานหรือจดรายจ่ายแทนการกดเอง โดยใช้ API key ของฉัน

## 6. ข้อมูลและกฎธุรกิจ

- เปอร์เซ็นต์ทักษะปัดลง (floor) เป็นจำนวนเต็ม
- 10 GB = 10 × 1024³ ไบต์ นับรวมทุกไฟล์ในการส่งหนึ่งครั้ง ข้อความไม่นับ ข้อความยาวไม่เกิน 10,000 ตัวอักษร
- เวลาหมดอายุของการส่งไฟล์เริ่มนับเมื่ออัปโหลดชิ้นสุดท้ายเสร็จ
- กราฟการเงินใช้ปีตามปฏิทิน ม.ค.–ธ.ค. ตามเขตเวลาเซิร์ฟเวอร์ เงินแสดงทศนิยม 2 ตำแหน่งเหมือนเดิม
- Google token และ API key เก็บแบบเข้ารหัสเหมือน API key AI ที่มีอยู่

## 7. รีไควร์เมนต์ไม่ใช่ฟังก์ชัน (non-functional)

- ทุกหน้าที่เปลี่ยนใช้ได้ทั้งมือถือ (375px) และคอม ทั้งธีมสว่างและมืด
- ไม่เพิ่ม Composer หรือ framework ใหม่ (repo ไม่มี Composer) ใช้ cURL เรียก Google/AI API ตรง
- Cloudflare Tunnel จำกัดขนาด request ราว 100 MB ชิ้นอัปโหลดต้องเล็กกว่านั้น
- ไฟล์ที่ส่งเก็บนอก web root และดาวน์โหลดแบบ attachment เสมอ

## 8. UX/UI

- flow ส่งไฟล์: เลือกไฟล์/ลากวาง + ช่องข้อความ → เลือกเวลาหมดอายุ → ส่ง → แถบความคืบหน้า → รหัส 6 หลัก + QR
- flow Drive: ตั้งค่า → เชื่อมบัญชี Google → เลือกโฟลเดอร์ → แถบความคืบหน้าการย้าย → เมนูไฟล์ใช้ได้
- หน้าตาใช้สไตล์พาสเทลเดิม (docs/REDESIGN-V3.md) ไม่สร้างสไตล์ใหม่

## 9. ข้อจำกัด

- เจ้าของระบบต้องสร้าง OAuth client ใน Google Cloud Console เอง (ผมเขียนคู่มือ) ทดสอบเฟส 4 ด้วยบัญชี Google จริงไม่ได้จนกว่าจะมี Client ID/Secret
- ค่า AI ทั้งหมดเป็นของผู้ใช้ผ่าน key ของตัวเอง เซิร์ฟเวอร์ไม่จ่าย
- Deploy เป็นงานของเจ้าของระบบ งานนี้จบที่ PR

## 10. ไม่ทำรอบนี้ (out of scope)

- หน้า "ยังไม่จัด" แยกของตัวเอง
- สร้าง/ลบหมวดเมนูเอง (ทำแค่เปลี่ยนชื่อและย้ายเมนูข้ามหมวด)
- ส่งไฟล์แบบหยุดแล้วทำต่อข้ามวัน (resume หลังปิดเบราว์เซอร์)
- เก็บไฟล์ส่งไฟล์ (transfer) ลง Drive: ยังอยู่บนเซิร์ฟเวอร์ชั่วคราวและหมดอายุใน 60 นาทีเหมือนเดิม
- Google Drive แบบ shared drive / Google Workspace ขององค์กร
- คำสั่ง AI นอกเหนือ REQ-27 (โน้ต ลิงก์ ตั้งค่า ฯลฯ ทยอยเพิ่มทีหลังบนโครงจาก REQ-26)
- เปิดให้ AI ภายนอก (MCP/API token) เข้ามาจัดการ

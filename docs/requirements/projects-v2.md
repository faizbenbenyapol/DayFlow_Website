# รีไควร์เมนต์: เมนูโปรเจกต์ v2 (โปรเจกต์หลายประเภท)

สถานะ: ยืนยันแล้ว (2026-11-23) · P0a ส่งมอบแล้ว 2026-11-24 (docs/handoff/projects-v2.md) · P0b–P3 ยังไม่เริ่ม
ระดับงาน: เต็ม (แก้หลายโมดูล เปลี่ยน schema ของงานในโปรเจกต์ที่มีข้อมูลจริง และมีเรื่องเงินในประเภทบัญชี)   ·   playbook: large-task

## 1. ปัญหาและเป้าหมาย
- ปัญหาจากมุมผู้ใช้: เมนูโปรเจกต์ตอนนี้มีบอร์ด 4 คอลัมน์ตายตัว (ต้องทำ / กำลังทำ / รอตรวจ / เสร็จแล้ว) ใช้ได้กับงานทั่วไปเท่านั้น งานพัฒนาซอฟต์แวร์ งานบัญชี และงานการตลาดต้องการเครื่องมือคนละแบบ
- เสร็จแล้วใครได้อะไร: ตอนสร้างโปรเจกต์เลือกประเภทได้ 4 แบบ แต่ละแบบเป็นเครื่องมือเต็มของงานนั้น ใช้คนเดียวหรือเป็นทีมก็ได้ ทั้งหมดอยู่ใน DayFlow ที่เดียว หน้าตาเป็นของ DayFlow เอง
- วัดความสำเร็จยังไง: เจ้าของใช้แต่ละประเภททำงานจริงได้ครบ flow โดยไม่ต้องเปิดโปรแกรมอื่น (เกณฑ์ราย REQ ด้านล่าง)

## 2. ผู้ใช้และสถานการณ์ใช้งาน
| ผู้ใช้ | ใช้ตอนไหน บนอุปกรณ์อะไร | สิ่งที่อยากทำให้สำเร็จ |
| --- | --- | --- |
| เจ้าของคนเดียว (ฟรีแลนซ์/งานส่วนตัว) | ทุกวัน คอมและมือถือ | วางแผนงาน ติดตามงาน ออกเอกสารเงิน โดยไม่ต้องมีทีม |
| เจ้าของโปรเจกต์ที่มีทีม | ทุกวัน | มอบหมายงาน อนุมัติค่าใช้จ่ายและโพสต์ เห็นภาพรวม |
| ผู้ดูแล | ทุกวัน | ตั้งค่าโปรเจกต์ เชิญคน อนุมัติแทนเจ้าของ |
| สมาชิก | ทุกวัน มือถือเป็นหลัก | เห็นงานของตัวเอง อัปเดตสถานะ ส่งขออนุมัติ |
| ผู้ดูอย่างเดียว / คนดูลิงก์แชร์ | เป็นครั้งคราว | ดูความคืบหน้า |

## 3. User stories
1. ในฐานะเจ้าของ ฉันอยากเลือกประเภทตอนสร้างโปรเจกต์ เพื่อได้เครื่องมือที่ตรงกับงานทันทีโดยไม่ต้องตั้งเอง
2. ในฐานะทีมพัฒนา ฉันอยากมีคลังงาน รอบงาน เลขงาน และแผนออกเวอร์ชัน เพื่อวางแผนและติดตามงานแบบทีมซอฟต์แวร์
3. ในฐานะทีมการตลาด ฉันอยากเห็นปฏิทินคอนเทนต์ทุกช่องทาง ส่งโพสต์ให้อนุมัติ และวัดผลแคมเปญเทียบงบ
4. ในฐานะคนทำบัญชี ฉันอยากตั้งงบ บันทึกค่าใช้จ่ายพร้อมใบเสร็จให้อนุมัติ และออกใบเสนอราคา/ใบแจ้งหนี้ที่เลขเอกสารเรียงถูก
5. ในฐานะสมาชิก ฉันอยากรู้ทันทีเมื่อได้งานใหม่ มีคนเรียกชื่อ หรือคำขอของฉันถูกอนุมัติ

## 6. ข้อมูลและกฎธุรกิจ
- สิทธิ์:

## 7. รีไควร์เมนต์ไม่ใช่ฟังก์ชัน (non-functional)
- บอร์ด 500 งานเปิดภายใน 1 วินาทีบนเครื่องทดสอบ ไม่มี query ใน loop (โหลดงาน ป้าย คน ในจำนวน query คงที่)
- ทุกหน้าจอใช้ได้ที่ 360px ถึงเดสก์ท็อป โหมดสว่าง/มืด สีโต๊ะทุกสี ผ่าน audit-layout
- ไม่มีไลบรารีภายนอกใหม่ ยกเว้นที่มีอยู่แล้ว (Chart.js สำหรับกราฟ)
- ทุก migration รันซ้ำได้ และไม่เปลี่ยน `updated_at` ของข้อมูลเดิม
- ชื่อ หน้าตา สี และไอคอนเป็นของ DayFlow ไม่ใช้ชื่อหรือหน้าตาของผลิตภัณฑ์อื่น (Jira, Asana, Monday.com, Notion, Trello, Airtable หรือโปรแกรม ERP)

## 8. UX/UI
- flow หลัก: สร้างโปรเจกต์ → เลือกประเภท (การ์ด 4 ใบพร้อมภาพย่อของหน้าตา) → ตั้งชื่อ ตัวย่อ (ซอฟต์แวร์) หรือผู้ออกเอกสาร (บัญชี, ข้ามไปก่อนได้) → เข้าหน้าโปรเจกต์ที่มีแท็บมุมมองของประเภทนั้น
- แท็บมุมมองต่อประเภท:
  - ทั่วไป: บอร์ด · รายการ · ปฏิทิน · ภาพรวม
  - ซอฟต์แวร์: รอบงาน · คลังงาน · แผนงาน · เวอร์ชัน · รายงาน
  - การตลาด: ปฏิทินคอนเทนต์ · บอร์ดโพสต์ · แคมเปญ · คลังไฟล์
  - บัญชี: ภาพรวมงบ · ค่าใช้จ่าย · เอกสารขาย · รายชื่อติดต่อ
- design plan: ต่อยอดธีม v3 (สมุดพาสเทลบนโต๊ะ) แต่ละประเภทมีสีประจำจากพาสเทลที่มี ก่อนลงมือแต่ละเฟส ส่งหน้าตาตัวอย่าง (mockup เป็นหน้าเว็บ) ให้เจ้าของเลือกก่อน
- ภาพอ้างอิงที่ผู้ใช้อนุมัติ: P0a = `docs/mockups/projects-v2-p0a.html` (อนุมัติ 2026-11-24, เลือกแก้คอลัมน์แบบ A คือรายการแยกตามกลุ่มในแท็บ "ตั้งค่า" ไม่ใช่แก้บนบอร์ด) เฟสอื่นทำก่อนลงมือแต่ละเฟส

## 12. สมมติฐานที่ใช้
- คอลัมน์ตั้งต้นของซอฟต์แวร์: ต้องทำ / กำลังทำ / รอรีวิว / ทดสอบ / เสร็จ; การตลาดตาม REQ-M2; บัญชีใช้ขั้นของค่าใช้จ่ายแทนบอร์ด — ถ้าผิดแก้ค่าตั้งต้นได้ เพราะคอลัมน์ตั้งเองได้อยู่แล้ว
- บทบาท "Editor" เดิมเท่ากับ "สมาชิก" ใหม่ — ถ้าผิด คนที่เคยแก้ได้จะยังแก้ได้เหมือนเดิม ไม่เสียสิทธิ์
- ความเห็นใหม่และการเปลี่ยนบนบอร์ดดึงข้อมูลใหม่ทุก 30–60 วินาที (polling) ไม่ใช้ WebSocket เพราะโฮสต์ PHP ธรรมดา — ถ้าต้องการทันทีแบบแชท ต้องเพิ่มเซิร์ฟเวอร์อีกตัว
- ใบเสนอราคา/ใบแจ้งหนี้ไม่ใช่ใบกำกับภาษี จึงไม่ต้องทำตามรูปแบบสรรพากรครบทุกข้อ — ถ้าต้องใช้เป็นใบกำกับภาษีด้วย ต้องเพิ่มเฟส

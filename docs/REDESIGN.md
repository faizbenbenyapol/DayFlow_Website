# DayFlow v2 — แผนออกแบบใหม่ทั้งเว็บ

แนวทาง: **ปฏิทินฉีก + สมุดบัญชี**
สถานะ: แผน (ยังไม่เริ่ม) · เขียนเมื่อ 2 ต.ค. 2569

> หลักการบรรทัดเดียว: เปิดแอปมาเจอ "หน้าของวันนี้" — เลขวันที่ตัวใหญ่บนแถบสีประจำวัน แล้วทุกอย่างที่เหลือเป็นรายการบนเส้นบรรทัดแบบสมุด ไม่ใช่กองการ์ด

## 0. ขอบเขต

**เปลี่ยน**
- หน้าตาและการจัดวางทุกหน้า: 24 view, หน้า login, หน้าแชร์, `offline.html`
- โครงนำทาง: sidebar, แถบบนมือถือ, ค้นหา ⌘K, จดด่วน
- CSS ทั้งหมด (~20,500 บรรทัด) และส่วนของ JS ที่สร้าง HTML เอง
- ระบบธีม: 6 ธีม → สว่าง / มืด / อัตโนมัติ + สวิตช์ "สีประจำวัน"

**ไม่เปลี่ยน**
- API, controller, model, ฐานข้อมูล — ยกเว้นข้อ 5 (ธีม, การตั้งค่า, เมนู)
- ไม่เพิ่ม framework หรือ build step — ยังเป็น PHP + CSS/JS ล้วนเหมือนเดิม
- รายงาน PDF ของ `finance.js` ยังใช้ inline style และ Sarabun ต่อไป เพราะต้องเปิดได้ด้วยตัวเอง

### 1.3 สีประจำวัน (`--day`, `--on-day`)

ใช้ **แค่ 2 จุด**: บล็อกวันที่บนหน้าวันนี้ และขีดบอกเมนูที่เปิดอยู่ (กว้าง 3px) ห้ามใช้เป็นสีปุ่ม สีลิงก์ หรือสีสถานะ

| วัน | `--day` | ตัวหนังสือบนสีนี้ (`--on-day`) | contrast |
|---|---|---|---|
| อาทิตย์ | `#C62828` | ขาว | 5.62 |
| จันทร์ | `#F2C200` | ink | 9.39 |
| อังคาร | `#E06C9F` | ink | 5.13 |
| พุธ | `#277A42` | ขาว | 5.32 |
| พฤหัสบดี | `#E8822A` | ink | 5.76 |
| ศุกร์ | `#2F6FC4` | ขาว | 5.01 |
| เสาร์ | `#7A4FBF` | ขาว | 5.68 |

- ตั้งจาก PHP ตามเขตเวลาของผู้ใช้: `<html data-day="fri">` แล้ว CSS เลือกค่าจาก attribute
- ถ้าปิดสวิตช์สีประจำวัน → `--day: var(--ink)`, `--on-day: var(--paper)`
- โหมดมืดใช้ค่าเดิม เพราะบล็อกวันที่เป็นพื้นทึบ ไม่ใช่ตัวหนังสือบนพื้นมืด

### 1.4 ตัวอักษร

| บทบาท | ฟอนต์ | หมายเหตุ |
|---|---|---|
| ทุกอย่าง | IBM Plex Sans Thai + IBM Plex Sans | ตระกูลเดียวกัน ไทยวางก่อนใน stack |
| ตัวเลขใหญ่ (วันที่, ยอดรวม) | IBM Plex Serif 500 | ให้รู้สึกเหมือนตัวพิมพ์บนปฏิทิน ใช้กับตัวเลขเท่านั้น |
| โค้ด, เวลาจับ, รหัสส่งไฟล์ | IBM Plex Mono | เฉพาะข้อมูลที่เป็นรหัสหรือนาฬิกาจริง |

- **ไฟล์ฟอนต์:** เพิ่ม `plexsans-latin-{400,500,600}`, `plexserif-latin-500`, `plexmono-latin-{400,500}` (self-host, woff2, subset) และลบ Inter 4 ไฟล์ Sarabun เก็บไว้ใช้กับรายงาน PDF
- **ขนาด (scale 1.25):** 13 / 16 / 20 / 25 / 31 / 39 และ 64–72 สำหรับเลขวันที่
- **ฐาน 16px** (เดิม 14.5px), line-height เนื้อความ 1.7, หัวข้อ 1.3, `letter-spacing: 0` ทุกที่
- **ตัวเลข:** `font-variant-numeric: tabular-nums` ทั้งระบบ เงินชิดขวาและมีทศนิยม 2 ตำแหน่งเท่ากันทั้งคอลัมน์
- **ห้าม** ALL-CAPS, ห้ามหัวข้อสีไล่, ห้ามบีบ letter-spacing

### 1.5 ระยะ, ความมน, ความลึก, การเคลื่อนไหว

- **ระยะห่าง:** ใช้ `--space-*` ชุดเดิม (4px base) แต่ระยะระหว่าง section ต้องต่างกันตามความสำคัญ ไม่ใช่เท่ากันทั้งหน้า
- **ความมน 3 ระดับ:**
  - `--r-control` 6px — ปุ่ม, ช่องกรอก
  - `--r-sheet` 10px — modal, popover, bottom sheet
  - 0 — แถวรายการ, ตาราง, section
- **เงา 2 ระดับ ใช้กับของที่ลอยจริงเท่านั้น:**
  - `--lift-1` — popover, toast, รายการที่กำลังลาก
  - `--lift-2` — modal, bottom sheet
  - ที่เหลือแยกชั้นด้วยเส้นหรือ `--paper-sunk`
- **Motion:**
  - `--dur: 160ms`, `--ease: cubic-bezier(.2,.0,.0,1)` แบบเดียวทั้งระบบ
  - ลบ easing เดิมทั้ง 7 แบบ รวม overshoot 1.56
  - การเคลื่อนไหวที่เกิดเองได้จุดเดียวทั้งแอป คือ "ฉีกหน้า" เมื่อเปลี่ยนวันในแพลนเนอร์
  - เคารพ `prefers-reduced-motion`
- **Focus:** `outline: 2px solid var(--ink); outline-offset: 2px` ทุก element ที่โฟกัสได้ ห้ามลบ outline

### 1.6 ไอคอน

- เก็บชุด SVG เส้น (lucide) ไว้ใช้แค่ 2 ที่: เมนูนำทางเมื่อพื้นที่แคบ (แถบล่างมือถือ, rail ย่อบน tablet) และปุ่มไอคอน (แก้ไข, ลบ, ปิด) · rail บน desktop เป็นตัวหนังสือล้วน (ตัดสินจาก mockup `docs/mockups/today.html`)
- ลบไอคอนออกจากหัว widget, การ์ดสถิติ และหัวข้อหน้า
- ย้าย SVG ที่เขียนซ้ำในทุก view ไปไว้ใน `views/partials/icons.php` (sprite ไฟล์เดียว + `<use href="#i-edit">`)
- ปุ่ม ✎ ✕ ที่เป็นตัวอักษร → ปุ่มไอคอนพร้อม `aria-label` และเป้ากด 44px บนมือถือ

| **เงิน** | รายรับรายจ่าย ← การเงิน · รายจ่ายประจำ ← การแจ้งเตือน · หุ้น ← ระบบหุ้น (Stocks) |

ตั้งค่าอยู่ล่างสุดของ rail แยกจากกลุ่ม หัวข้อหน้า (h1) ต้องตรงกับชื่อในเมนูทุกหน้า (ตอนนี้ทั้ง `/files` และ `/file-tools` ใช้หัวข้อ "จัดการไฟล์" ซ้ำกัน)

### 2.2 Desktop (≥1024px)

```
┌──────────┬────────────────────────────────────────────────┐
│ DayFlow  │ หัวหน้า: ชื่อหน้า + ปุ่มหลัก 1 ปุ่ม      [ค้นหา ⌘K] │
│──────────│────────────────────────────────────────────────│
│ วันนี้     │                                                │
│ ▌งาน     │  เนื้อหา (กว้างสุด 1200px ชิดซ้าย ไม่จัดกลาง)      │
│ โปรเจค   │                                                │
│ ...      │                                                │
│──────────│                                                │
│ ตั้งค่า    │                                                │
│ ชื่อผู้ใช้   │                                                │
└──────────┴────────────────────────────────────────────────┘
```

- rail ซ้ายกว้าง 220px พื้น `--paper-sunk` แบ่งจากเนื้อหาด้วยเส้น `--rule` (ไม่ใช้เงา)
- เมนูที่เปิดอยู่: ขีด `--day` 3px ด้านซ้าย + ตัวหนา (ไม่ใช้พื้นทึบ)
- ไม่มี topbar แยก หัวของแต่ละหน้าเป็นส่วนของเนื้อหา

### 2.3 Tablet (768–1023px)

rail ย่อเหลือไอคอน 64px และแสดงชื่อเป็น tooltip

### 2.4 มือถือ (<768px)

```
┌─────────────────────────────┐
│ ชื่อหน้า                 [⌕] │
│                             │
│ เนื้อหา                      │
│                             │
├─────┬─────┬─────┬─────┬─────┤
│วันนี้ │ งาน │  ＋  │ เงิน │ทั้งหมด│
└─────┴─────┴─────┴─────┴─────┘
```

- แถบล่าง 5 ช่อง สูง 56px + `env(safe-area-inset-bottom)`
- ＋ เปิด bottom sheet "จดด่วน" ที่เลือกได้ว่าจะเป็น งาน / จดด่วน / รายจ่าย (ใช้ API เดิมของแต่ละโมดูล)
- "ทั้งหมด" เปิด sheet รายการเมนูครบทุกกลุ่ม (แทนปุ่ม hamburger)
- ช่องประจำในแถบล่างปรับได้ในตั้งค่า → เมนู

### 2.5 ⌘K / ค้นหา

ใช้ `cmdk` เดิม แต่จัดหน้าตาใหม่และเพิ่มคำสั่งด่วน: "เพิ่มงาน", "บันทึกรายจ่าย", "ไปวันที่…"

### 2.6 โหมดแชร์

แถบบนสีหมึกบาง ๆ บอก "คุณกำลังดูของ … (อ่านอย่างเดียว)" ปุ่มแก้ไขทุกปุ่มต้องไม่ถูก render เลย ไม่ใช่แค่ซ่อนด้วย CSS

## 3. Component และ pattern

| ชื่อ | กติกา |
|---|---|
| **หัวหน้า** (`.page-head`) | h1 25px + บรรทัดรองสีดินสอ (ตัวเลขจริง เช่น "ค้าง 3 · เสร็จวันนี้ 2") + ปุ่มหลักขวาสุด 1 ปุ่ม |
| **แถวสมุด** (`.ruled-list`, `.ruled-row`) | pattern หลักของแอป แทนการ์ด แถวสูงขั้นต่ำ 44px เส้นล่าง `--rule` ซ้ายเป็นช่องติ๊ก/สัญลักษณ์ ขวาเป็นข้อมูลรอง (วันที่, จำนวน) |
| **ตารางบัญชี** (`.ledger`) | ตัวเลขชิดขวา tabular, แถวยอดรวมมีเส้นคู่ (`border-top: 3px double`), ยอดติดลบเป็นสีแดงและมีเครื่องหมายลบด้วย (ไม่สื่อด้วยสีอย่างเดียว) |
| **บล็อกวันที่** (`.date-block`) | พื้น `--day` + เลขวันที่ Plex Serif ใช้บนหน้าวันนี้ แพลนเนอร์ และหัวกลุ่มรายวันในหน้าอื่น |
| **Section** (`.sheet`) | กล่องเส้นขอบ 1px `--rule` มุม 0 ใช้เฉพาะเมื่อต้องรวมกลุ่มจริง ๆ ห้ามซ้อน section ในกล่อง |
| **ปุ่ม** | `primary` (พื้น ink), `secondary` (ขอบ rule-strong), `ghost`, `danger` (ตัวแดง ขอบแดง) · หน้าละ primary 1 ปุ่ม · ข้อความเป็นกริยา + สิ่งที่ทำ: "บันทึกรายจ่าย" ไม่ใช่ "บันทึก" |
| **ช่องกรอก** | label อยู่บนเสมอ, ขอบ `--rule-strong`, พื้น `--paper`, error อยู่ใต้ช่องเป็นสีแดง + ไอคอน, hint บอกรูปแบบก่อนพิมพ์ |
| **สถานะ vs แท็ก** | สถานะ (เกินกำหนด, เสร็จ) = ตัวหนังสือสี + สัญลักษณ์ ไม่มีพื้น · แท็ก/หมวด = ขอบบาง มุม 4px สีดินสอ · ไม่มี pill มนสุดอีกต่อไป |
| **Modal** | desktop: กลางจอ กว้าง 520px · มือถือ: bottom sheet ลากปิดได้ · ปุ่มยืนยันอยู่ขวาล่างและใช้คำเดียวกับปุ่มที่เปิด |
| **Toast** | ล่างกลาง (มือถืออยู่เหนือแถบล่าง) ข้อความพูดผลลัพธ์ "ลบงานแล้ว" + ปุ่ม "เลิกทำ" เมื่อลบ |
| **Tabs** | เส้นใต้ ink 2px ไม่ใช้กล่องพื้นทึบ · บนมือถือเลื่อนแนวนอนได้ |
| **Empty state** | ประโยคชวนลงมือ + ปุ่มเดียว เช่น "ยังไม่มีรายจ่ายเดือนนี้ — บันทึกรายการแรก" ไม่มีภาพประกอบ |
| **Loading** | skeleton เป็นแถวเส้นบรรทัดสีจาง จำนวนเท่าข้อมูลที่คาด ห้ามมี spinner กลางกล่อง (spinner ใช้ได้แค่ในปุ่มที่กำลังส่ง) |
| **Error** | บอกสาเหตุ + ทางแก้ + ปุ่มลองใหม่ ในตำแหน่งที่ข้อมูลควรอยู่ |
| **กราฟ** (Chart.js) | helper `chartTheme()` อ่านสีจาก CSS variable · แนวโน้มใช้เส้นไม่มี fill, เทียบใช้แท่ง, ห้ามโดนัท (สัดส่วนใช้แท่งซ้อน 100%) |

ทุก component ต้องมี: ข้อความยาว 60 ตัวอักษร, ตัวเลข 8 หลัก, โหมดมืด, กว้าง 375px, และ focus ที่มองเห็นได้

## 4. แผนรายหน้า

ขนาดงาน: S = ไม่กี่ชั่วโมง, M = 1 วัน, L = 2–3 วัน (ประเมินจากจำนวนบรรทัด CSS/JS และ inline style)

## 5. การเปลี่ยนฝั่ง backend (มีเท่านี้)

1. **Migration `027_redesign_settings.sql`**
   - `UPDATE user_settings SET theme='light' WHERE theme IN ('soft','lavender','ocean','peach')`

   - เพิ่มคอลัมน์ `day_color TINYINT(1) NOT NULL DEFAULT 1`
   - เพิ่มคอลัมน์ `mobile_tabs JSON NULL` (ช่องในแถบล่างมือถือ)

3. **`DashboardLayout`:** API เดิมใช้ต่อ (เทสต์ `dashboard_test.php` ยังผ่าน) เปลี่ยนแค่ widget key ให้ตรงกับ section ใหม่ของหน้าวันนี้ และย้ายการจัดเรียงไปหน้าตั้งค่า
4. **header:**
   - คำนวณ `data-day` จากเขตเวลาผู้ใช้
   - อัปเดต `<meta name="theme-color">` (ตอนนี้เป็น `#111827`) ให้ตรงกับ `--paper` สว่าง/มืด

7. **`DemoReset`:** ข้อมูล demo ใช้วันที่ตายตัวเดือนกรกฎาคม ทำให้งานทุกแถว "เกินกำหนด" ต้องแก้ให้วันที่เลื่อนตามวันปัจจุบัน ไม่งั้นภาพหน้าจอและหน้า demo จะดูพัง

## 6. แนวทางเทคนิค

### โครงไฟล์ CSS ใหม่

```
public/assets/css/
  fonts.css        ฟอนต์ self-host
  tokens.css       ค่าทั้งหมดในข้อ 1 + ธีมมืด + สีประจำวัน
  base.css         reset, ตัวอักษร, ลิงก์, focus, reduced-motion
  shell.css        rail, แถบล่างมือถือ, หัวหน้า, sheet, ⌘K, โหมดแชร์
  components.css   ทุกอย่างในข้อ 3
  utilities.css    utility ชุดเล็ก (มีชุดเดิมอยู่แล้ว — คัดเฉพาะที่ใช้จริง)
  modules/*.css    เฉพาะสิ่งที่หน้านั้นมีคนเดียว
```

`app.css` ปัจจุบันจะถูกแตกเข้า tokens/base/shell แล้วลบทิ้ง

### กติกาโค้ด

- **ชั้นแปลชื่อเก่า (ชั่วคราว):** ช่วง Phase 1–5 ให้ `--color-text`, `--color-surface`, `--shadow*`, `--palette-*` ฯลฯ ชี้ไปที่ token ใหม่ เพื่อให้หน้าที่ยังไม่ได้ทำไม่พัง แล้วลบทั้งหมดใน Phase 6
- **ห้ามเพิ่มของใหม่ต่อไปนี้:** `!important` (ยกเว้น utility ซ่อน/แสดง), inline style (ยกเว้นค่าจากข้อมูล เช่นความกว้างแถบ % และสีหมวดที่ผู้ใช้เลือก ซึ่งต้องส่งผ่าน `style="--cat: …"` เท่านั้น), สี hex นอก `tokens.css`
- **ทำโมดูลไหน ล้างหนี้ของโมดูลนั้นให้หมด:** inline style, `!important`, สี hardcode ใน view, JS และ CSS ของมัน
- **JS ที่สร้าง HTML:** ใช้ class จาก components แทน `style=""` · การซ่อน/แสดงใช้ attribute `hidden` แทน `style.display`
- **Chart.js:** `chartTheme()` ใน `app.js` อ่าน `getComputedStyle` แล้ววาดใหม่เมื่อธีมเปลี่ยน
- **ชื่อ class:** ตามแบบเดิม (kebab-case, prefix ตามโมดูล เช่น `fin-`, `stk-`)

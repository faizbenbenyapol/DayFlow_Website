## 2. Audit หน้าจอ (`scripts/audit-layout.mjs`)

ครอบคลุม:
- **24 หน้าในแอป** (รวมหน้าแก้ไขโน้ตและหน้า 404) และ **5 หน้านอกแอป** (เข้าสู่ระบบ, สมัครสมาชิก, 404 ตอนยังไม่ล็อกอิน, offline, ลิงก์แชร์หมดอายุ)
- **4 ความกว้าง**: 320px (มือถือเล็ก), 390px (มือถือ), 820px (แท็บเล็ต), 1366px (จอใหญ่)
- **ทุก dialog** ในแต่ละหน้า เปิดทีละอันแล้วตรวจข้างใน
- **3 รอบ**: บัญชีที่มีข้อมูลในโหมดสว่าง, โหมดมืด, และบัญชีที่ยังไม่มีข้อมูล (ดูหน้าว่างทุกหน้า)

สิ่งที่ตรวจ:
- หน้าเลื่อนแนวนอน · กล่องล้นขอบหน้า · ตัวหนังสือล้นปุ่มหรือป้าย · ปุ่มหรือช่องกรอกทับกัน · scrollbar ที่โผล่มาโดยไม่ตั้งใจ · มีอะไรวาดทับ dialog ที่เปิดอยู่
- ตัวหนังสือที่ contrast ต่ำกว่า WCAG (4.5:1, หรือ 3:1 สำหรับตัวใหญ่) โดยวัดจากสีที่แสดงจริงบนพื้นจริง
- ปุ่ม ลิงก์ ช่องกรอกที่ screen reader อ่านชื่อไม่ได้ · id ซ้ำในหน้า · รูปไม่มี alt

## 5. ข้อจำกัดของ QA รอบนี้

- **ดรอปดาวน์แบบใหม่** ทดสอบได้เฉพาะใน Chromium (Chrome 152 ของ browser pane และ headless) ส่วน Firefox กับ Safari จะเห็นรายการแบบของระบบ ซึ่งเป็นพฤติกรรมที่ตั้งใจ แต่ไม่ได้เปิดดูจริงในสองเบราว์เซอร์นั้น
- **ไม่ได้ทดสอบบนมือถือจริง** มีแค่การจำลองขนาดจอและ touch ใน Chromium
- **service worker** ลงทะเบียนไม่ได้ใน browser pane จึงตรวจได้แค่ว่าไฟล์ที่ cache มีอยู่ครบ ไม่ได้ทดสอบการทำงานแบบ offline จริง
- **ข้อทดสอบที่ขึ้นกับเวลา** 3 ข้อ (dashboard 2, focus 1) เคยล้มหนึ่งรอบแล้วผ่านในรอบถัดไปโดยไม่ได้แก้โค้ด เป็นปัญหาเดิมที่บันทึกไว้แล้ว (นาฬิกา MariaDB เป็น UTC แต่ PHP เป็นเวลาไทย) ยังไม่ได้แก้ในรอบนี้

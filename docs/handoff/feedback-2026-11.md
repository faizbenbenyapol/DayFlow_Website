## 1. สรุปสิ่งที่ส่งมอบ

เฟส 1 แก้จุดกวนใจที่เจอจากการใช้จริงและทำกราฟการเงินใหม่ เมนู "ยังไม่จัด" หายจากทุกที่ที่แสดงเมนู แต่กล่อง "ยังไม่จัด" ในหน้างานยังอยู่ ติ๊กงาน งานโปรเจกต์ หรือนิสัยแล้วไม่มีป๊อปอัพเด้ง (ยกเว้นตอนบันทึกไม่สำเร็จ) เปอร์เซ็นต์เป้าหมายทักษะเป็นจำนวนเต็ม เปลี่ยนหน้าแล้วเนื้อหาไม่ขยับซ้ายขวา กราฟการเงินมีแท่งมน สีที่อ่านออกทั้งธีมสว่างและมืด สลับดูได้สามมุมมอง (รายเดือน ตามหมวด ก้อนใหญ่สุด 10 อันดับ) และปีที่ไม่มีรายการบอกเป็นข้อความแทนแกนเปล่า

เฟส 2 ทำให้ผู้ใช้จัดเมนูเองได้: เปลี่ยนชื่อหมวดใหญ่ทั้ง 6 ย้ายเมนูไปหมวดอื่น (หน้านั้นเปลี่ยนเป็นสีของหมวดใหม่) ค้นหาเมนูในหน้าตั้งค่า และคืนค่าเริ่มต้นได้ในปุ่มเดียว หน้าตั้งค่ามีแท็บ "เกี่ยวกับแอป" ที่บอกเวอร์ชัน 3.0.0 พร้อมรายการสิ่งที่เปลี่ยนของทุกเวอร์ชันเป็นภาษาคนทั่วไป และปุ่มติดตั้ง DayFlow ลงเครื่อง (บน iPhone/iPad แสดงวิธีกดแทน)

เฟส 3 ทำให้ส่งไฟล์ได้ทุกประเภท กี่ไฟล์ก็ได้ รวมไม่เกิน 10 GB ไฟล์ใหญ่อัปโหลดทีละชิ้นพร้อมแถบความคืบหน้า และลองใหม่เองเมื่อเน็ตสะดุด ส่งข้อความหรือลิงก์ได้ทั้งแบบมีและไม่มีไฟล์ เลือกเวลาหมดอายุ 5, 15, 30 หรือ 60 นาทีได้ ผู้รับที่ไม่มีบัญชีใส่รหัสที่ /transfer/receive หรือสแกน QR แล้วเห็นข้อความ (ลิงก์กดได้ มีปุ่มคัดลอก) และดาวน์โหลดทีละไฟล์ หรือรวมเป็น ZIP เมื่อรวมไม่เกิน 2 GB

เฟส 4 ให้ผู้ใช้เก็บไฟล์ใน Google Drive ของตัวเองได้ กด "เชื่อมบัญชี Google" ในตั้งค่า > Google Drive แล้ว DayFlow สร้างโฟลเดอร์ "DayFlow" ใน My Drive ย้ายไฟล์เดิมขึ้นไปพร้อมโครงโฟลเดอร์ (แถบความคืบหน้าบนหน้าตั้งค่า ปิดหน้าแล้ว cron ย้ายต่อ) และไฟล์ใหม่ไปเก็บใน Drive ส่วนเมนูไฟล์ใช้เหมือนเดิมทุกคำสั่ง รวมลิงก์แชร์ที่สร้างไว้ก่อน ผู้ใช้ที่ไม่เชื่อมใช้เหมือนเดิมทุกอย่างและไม่มีคำขอไป Google เลย เจ้าของระบบต้องสร้าง OAuth client ตาม `docs/guides/google-drive-setup.md` ก่อน ความสามารถนี้จึงจะเปิด

เฟส 5 ให้ผู้ใช้พิมพ์สั่ง AI ในหน้าผู้ช่วย AI แท็บ "สั่งงาน" ด้วย key ของตัวเอง: เพิ่ม ดู ติ๊ก และลบงาน ติ๊กนิสัย จดและดูรายรับรายจ่าย คำสั่งลบต้องกดยืนยันก่อนเสมอ ใส่ key ได้ 12 เจ้า (เพิ่ม DeepSeek, Mistral, Groq, xAI, Together AI, Qwen) และ "OpenAI-compatible (URL เอง)" สำหรับบริการอื่นที่ใช้ API แบบ OpenAI ใส่ชื่อโมเดลเองได้ทุกเจ้า URL เองชี้เข้าเครือข่ายภายในของเซิร์ฟเวอร์ไม่ได้ เว้นเจ้าของระบบเปิด error จากผู้ให้บริการเป็นภาษาไทยพร้อมชื่อเจ้า คำสั่งใหม่เพิ่มได้ด้วยการวางไฟล์เดียวใน `core/ai-commands/` ผู้ใช้ที่ไม่ใส่ key ไม่เห็นอะไรเปลี่ยน

## 4. ความต้องการของระบบและการติดตั้ง

- เฟส 1: ไม่มี migration ไม่มีตัวแปรสภาพแวดล้อมใหม่ ไม่มี dependency ใหม่ ใช้ Chart.js 4.4.0 เดิม
- เฟส 3: migration ใหม่ `sql/migrations/034_transfer_chunks.sql` เพิ่ม `file_transfers.message`, `status` ('uploading'/'ready', เดิมเป็น 'ready'), `expiry_minutes` รันซ้ำได้ PHP ต้องรับคำขอได้อย่างน้อย 8 MB (`post_max_size` ตอนนี้ 22M) เพราะไฟล์ถูกส่งเป็นชิ้นละ 8 MB
- เฟส 4: migration ใหม่ `sql/migrations/035_google_drive.sql` เพิ่ม `files.drive_id` (NULL = ไฟล์อยู่บนเซิร์ฟเวอร์) + index `idx_user_drive` และตาราง `drive_links` (ผู้ใช้ละแถว token เข้ารหัสด้วย APP_KEY, ลบตามบัญชีด้วย FK CASCADE) รันซ้ำได้ ไม่มี backfill ตัวแปรสภาพแวดล้อมใหม่ `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET` (ว่าง = ปิดความสามารถ Drive) และ `GOOGLE_AUTH_URL`/`TOKEN_URL`/`REVOKE_URL`/`API_URL` ที่ production ไม่ต้องตั้ง (ว่างแล้วใช้ที่อยู่จริงของ Google) ไม่มี dependency ใหม่ ใช้ curl ที่มีอยู่
- เฟส 5: migration ใหม่ `sql/migrations/036_ai_key_endpoint.sql` เพิ่ม `user_ai_keys.base_url` (VARCHAR 500) และ `model` (VARCHAR 120) NULL ได้ รันซ้ำได้ ไม่มี backfill key เดิมใช้ต่อด้วยโมเดลเริ่มต้นเหมือนก่อน ตัวแปรสภาพแวดล้อมใหม่ `AI_ALLOW_PRIVATE_URLS` (ว่าง = บล็อก URL ภายใน, `true` = ยอมให้ URL เองชี้เครื่องเดียวกันหรือเครือข่ายภายใน เช่น Ollama) ไม่มี dependency ใหม่
- เฟส 2: migration ใหม่ `sql/migrations/033_menu_layout.sql` เพิ่มคอลัมน์ `user_settings.menu_layout` (JSON, NULL ได้) รันซ้ำได้ ไม่มี backfill ผู้ใช้เดิมเห็นเมนูเหมือนเดิม ไม่มีตัวแปรสภาพแวดล้อมใหม่

## 5. การรันและการนำขึ้นระบบ (deploy)

รันเหมือนเดิม (ดู CLAUDE.md) deploy เป็นงานของเจ้าของระบบ ไฟล์ CSS/JS ใหม่ถูกโหลดเองด้วย `?v=` เดิม

**เฟส 3:** migration 034 ต้องรันพร้อมโค้ด ไม่งั้นการส่งไฟล์ทั้งหมดใช้ไม่ได้ (คอลัมน์ status ไม่มี) และ cron (`php cron.php` ทุก 5 นาที ตามที่ตั้งอยู่แล้ว) เป็นตัวลบไฟล์ที่หมดอายุและที่อัปโหลดค้าง ถ้า cron ไม่ทำงาน รหัสยังหมดอายุตรงเวลา แต่ไฟล์จะค้างบนดิสก์จนมีคนเปิดหน้าส่งไฟล์

**เฟส 2 ต้องรัน migration ก่อนเปิดใช้:** `php scripts/migrate.php` (รันแล้วในเครื่องทดสอบ: ครั้งแรก "1 applied" และ `--force` ซ้ำไม่มี error) ถ้าไม่รัน การบันทึกในหน้าตั้งค่าเมนูจะได้ "บันทึกการตั้งค่าเมนูไม่สำเร็จ" ส่วนหน้าอื่นใช้ค่าตั้งต้นต่อได้ (อนุมาน จากโค้ด `menu_layout ?? 'null'`)

**เฟส 4:** รัน migration 035 พร้อมโค้ด แล้วทำตาม `docs/guides/google-drive-setup.md` (สร้าง OAuth client, ใส่สองค่าใน `.env`, publish แอปใน Google ก่อนเปิดให้ทุกคนใช้ ไม่งั้นการเชื่อมหลุดทุก 7 วัน) ต้องเปิด worker (`--profile prod-worker`) ด้วย ไม่งั้นการย้ายไฟล์เดิมหยุดเมื่อผู้ใช้ปิดหน้าตั้งค่า ถ้ายังไม่ใส่ค่า หน้าตั้งค่าบอกว่า "เจ้าของระบบยังไม่ได้เปิดใช้" และทุกอย่างทำงานแบบเดิม Google ปลอมอยู่ใน `docker-compose.override.yml` ซึ่ง production ไม่โหลดเพราะระบุ `-f` เอง (ตรวจแล้วด้วย `docker compose -f docker-compose.yml -f docker-compose.prod.yml config` ไม่มีที่อยู่หรือบริการของ Google ปลอม)

**เฟส 5:** รัน migration 036 พร้อมโค้ด ไม่งั้นการบันทึกและอ่าน key AI ทั้งหมดล้ม (คอลัมน์ base_url/model ไม่มี) อย่าตั้ง `AI_ALLOW_PRIVATE_URLS=true` บนเซิร์ฟเวอร์ที่เปิดให้คนทั่วไปสมัคร เว้นแต่ยอมให้ผู้ใช้ทุกคนให้เซิร์ฟเวอร์ยิงเข้าเครือข่ายภายในได้ AI ปลอมอยู่ใน `docker-compose.override.yml` เหมือน Google ปลอม production จึงไม่โหลด

เลขเวอร์ชันที่แอปแสดงมาจากตัวแรกใน `config/releases.php` (ตอนนี้ 3.0.0) ติด tag git ให้ตรงตอน deploy และใส่วันที่ของเวอร์ชันนั้นในไฟล์

- เฟส 4: เปลี่ยนสถานะใน drive_links ผ่าน `DriveLink::setState($id, $from, $to)` เท่านั้น และระบุ `$from` ให้แคบที่สุด อย่าเขียน `UPDATE drive_links SET state` ตรง ๆ (เคยทำให้การย้ายเขียนทับ "ยกเลิกการเชื่อม" ของผู้ใช้)
- เฟส 4: แถวที่อยู่ใน Drive ต้องมีโฟลเดอร์แม่ทุกชั้นอยู่ใน Drive ด้วย (`ensureDriveFolder` สร้างให้เอง) อย่าสร้างแถวใน Drive โดยข้ามฟังก์ชันนี้

  3. test ยังเขียวแม้ตัดการเทียบขนาด หรือลบไฟล์ก่อนบันทึก drive_id → เพิ่ม test สำเนาขาด (`/_fake/truncate`) และ test ฐานข้อมูลล้มหลังอัปโหลด (trigger ชั่วคราว)

  5. ไฟล์ที่หายจากดิสก์ทำให้แถบความคืบหน้าค้าง → แถบขึ้นเฉพาะสถานะ migrating / paused_full

## 13. งานถัดไปที่แนะนำ

- เจ้าของระบบทำตาม `docs/guides/google-drive-setup.md` แล้วทดสอบเฟส 4 กับ Google จริง (หัวข้อ 6 ของคู่มือ) ก่อนเปิดให้ผู้ใช้
- เฟส 5 ต่อ: คำสั่ง AI ที่เหลือ (โน้ต ลิงก์ ฯลฯ) ด้วยการเพิ่มไฟล์ใน `core/ai-commands/`; ซ่อนตัวอย่างคำสั่งหลังเริ่มคุย และแก้หัวหน้า /ai ให้พูดถึงการสั่งงาน
- ทีหลัง: Google Picker ให้เลือกโฟลเดอร์เอง (CR-1) และเครื่องมือดึงไฟล์จาก Drive กลับเซิร์ฟเวอร์
- เสนอเพิ่มใน CLAUDE.md: `php -S` ในคอนเทนเนอร์ใช้ OPcache แบบ production (`validate_timestamps=0`) แก้ไฟล์แล้วไม่มีผลจนรีสตาร์ท ต้อง mount `docker/php.dev.ini`; ของที่ใช้แค่ทดสอบให้ใส่ `docker-compose.override.yml` ไม่ใช่ `docker-compose.yml`
- แก้สกิล opencode-delegate ให้ใช้โมเดลที่ยังมีในแพ็กเกจ (`opencode-go/deepseek-v4.1-flash`) หรือโมเดลที่ผู้ใช้เลือก
- เสนอเพิ่มใน CLAUDE.md: `scripts/screenshots.mjs` เปิด Chrome ด้วย `--hide-scrollbars` จึงตรวจเรื่องแถบเลื่อนไม่ได้ ต้องเปิด Chrome เองโดยไม่ใส่ธงนี้; ภาพ `captureBeyondViewport` บนมือถือไม่วาด canvas ที่อยู่นอกจอ

## 1. สรุปสิ่งที่ส่งมอบ

หน้า "งาน" แตกงานส่วนตัวเป็นเช็กลิสต์งานย่อยได้ (เพิ่ม ติ๊ก แก้ชื่อ ลบ ลากเรียง) การ์ดงานบอกความคืบหน้าเช่น "☑ 2/5" และตั้งวันกับเวลาให้แอปเตือนงานนั้นได้ ถึงเวลาแล้วแอปส่งเตือนที่มีชื่องานทั้งทาง Telegram (ถ้าตั้งบอทไว้) และทางการแจ้งเตือนของเบราว์เซอร์ (Web Push) งานทำซ้ำพางานย่อยและเวลาเตือนไปรอบถัดไปเอง ระหว่างทางยังซ่อมการแจ้งเตือนของเบราว์เซอร์ที่เงียบไปตั้งแต่ 3 ต.ค. 2026 ให้กลับมาแสดงอีกครั้ง

## 6. คู่มือการใช้งาน

แตกงานเป็นงานย่อย
1. หน้า "งาน" กดชื่องาน เปิดหน้าต่างแก้ไขงาน
2. ส่วน "งานย่อย" พิมพ์ในช่อง "เพิ่มงานย่อย แล้วกด Enter" แล้วกด Enter ทีละข้อ
3. ติ๊กช่องหน้างานย่อยเมื่อเสร็จ บันทึกทันทีโดยไม่ต้องกด "บันทึกงาน"
4. ลากที่จุด ⋮⋮ เพื่อเรียง กดไอคอนถังขยะเพื่อลบ
5. การ์ดงานขึ้น "☑ เสร็จ/ทั้งหมด" งานหลักไม่ปิดเองแม้ติ๊กครบ

ตั้งเวลาเตือน
1. ในหน้าต่างงาน เลือก "เตือนวันที่" และ "เวลา" แล้วกด "บันทึกงาน"
2. การ์ดขึ้น "🔔 เวลา" (หรือ "🔔 วัน เดือน เวลา" ถ้าไม่ใช่วันนี้)
3. ไม่ต้องการเตือนแล้ว กด "ล้างเวลาเตือน" แล้วบันทึก

ข้อความที่อาจเจอ

| ข้อความ | แปลว่า | แก้ยังไง |
| --- | --- | --- |
| เวลาเตือนผ่านไปแล้ว | เลือกเวลาที่ผ่านมาแล้ว | เลือกเวลาในอนาคต |
| ยังไม่ได้เปิดการแจ้งเตือน | บัญชีไม่มีทั้งบอท Telegram และเบราว์เซอร์ที่เปิดแจ้งเตือน | กด "เปิดในตั้งค่า" แล้วเปิดอย่างน้อยหนึ่งช่องทาง |
| งานย่อยเต็มแล้ว (100 รายการ) | งานหนึ่งมีงานย่อยได้ไม่เกิน 100 | แตกเป็นงานหลักใหม่ |

## 7. โครงสร้างระบบสำหรับผู้ดูแล

```
หน้าต่างงาน (tasks.js) ──API──> TaskController / TaskSubtaskController ──> tasks, task_subtasks
                                                                          │
cron.php ทุก 5 นาที ── Task::dueReminders() ──> ส่ง Telegram ──> Task::markReminded()
                                                               └──> PushSubscription::notifyUser()
                                                                          │ (push ไม่มีเนื้อหา)
sw.js รับ push ──> GET /api/push/pending ──> NotificationDigest (เตือนมาก่อน) ──> แสดงแจ้งเตือน
```

| ไฟล์ | หน้าที่ |
| --- | --- |
| sql/migrations/030_task_subtasks_reminders.sql | ตาราง task_subtasks และคอลัมน์ tasks.remind_at, tasks.reminded_at |
| models/TaskSubtask.php | อ่าน เขียน เรียงงานย่อย กรองตามเจ้าของทุก query |
| controllers/TaskSubtaskController.php | API งานย่อย 5 เส้น |
| models/Task.php | จำนวนงานย่อยใน query เดียว, remind_at, รอบถัดไปของงานทำซ้ำ, เลือกและ mark เตือน |
| cron.php ส่วน 1.5 | ส่งเตือนตามเวลา |
| core/NotificationDigest.php | รายการที่เบราว์เซอร์จะแสดง เตือนมาก่อนเพราะ sw.js แสดงแค่ 3 รายการแรก |
| public/sw.js | รับ push และการกดแจ้งเตือน |

จุดที่ต้องระวังเวลาแก้ต่อ
- ใน `Task::update` บรรทัด `reminded_at = IF(remind_at <=> ?, ...)` ต้องอยู่ก่อน `remind_at = ?` เพราะ MariaDB คำนวณ SET จากซ้ายไปขวา
- ส่วน 1.5 ของ cron ต้องอยู่ก่อนส่วน 2 เพราะส่วน 2 `return` ออกเมื่อไม่มีใครตั้ง Telegram
- `markReminded` ต้องเกิดก่อนปลุกเบราว์เซอร์ เพราะเบราว์เซอร์หาเตือนจาก `reminded_at`
- Telegram กับ Web Push ต้องไม่ขึ้นต่อกัน Telegram ล้มแล้วยังต้องปลุกเบราว์เซอร์
- โปรเจกต์เปิด `PDO::MYSQL_ATTR_FOUND_ROWS` ไว้ `rowCount()` จึงนับแถวที่ตรงเงื่อนไข ไม่ใช่แถวที่ค่าเปลี่ยน
- ตารางใหม่ที่เป็นข้อมูลของผู้ใช้ต้องเพิ่มใน `AccountData::TABLES` เสมอ

## 9. ข้อจำกัด ความเสี่ยง และหนี้เทคนิค

- ความแม่นยำของเวลาเตือนไม่เกิน 5 นาที ตามรอบ cron
- เวลาเตือนใช้เขตเวลาของเซิร์ฟเวอร์ (`TIMEZONE`) เหมือนทั้งหน้าเว็บ
- เตือนทาง Telegram ส่งแม้ผู้ใช้ปิดสวิตช์ "งาน" ในตั้งค่า Telegram เพราะเป็นเตือนที่ผู้ใช้ตั้งเองทีละงาน (ใช้ประเภทเหตุการณ์ `reminder` ซึ่งยังไม่มีสวิตช์ในหน้าตั้งค่า)
- เมื่อ CR-1 ซ่อม service worker แล้ว สรุปรายวัน (งานเกินกำหนด ครบกำหนดวันนี้ ใกล้ตัดเงิน) จะกลับมาเด้งในเบราว์เซอร์อีก
- เทสต์ชุดเต็มรัน 5 รอบในวันส่งมอบ ตก 2 รอบ รอบละ 1 ข้อ แล้วผ่านเมื่อรันซ้ำโดยไม่แก้โค้ด รอบแรกคือ `guessing transfer codes is throttled per client` (สุ่ม IP ทดสอบจาก 254 ค่า น่าจะชนกับรอบก่อนในหน้าต่าง 10 นาที อนุมาน) รอบที่สองระบุไม่ได้ว่าข้อไหนเพราะไม่ได้เก็บ output เต็ม งานนี้ไม่ได้แตะระบบส่งไฟล์หรือ rate limiter
- ไม่ทำรอบนี้: ดูหัวข้อ 10 ของไฟล์รีไควร์เมนต์

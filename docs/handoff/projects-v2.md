## 1. สรุปสิ่งที่ส่งมอบ

ตอนสร้างโปรเจคเลือกได้ 4 ประเภท (ทั่วไป / พัฒนาซอฟต์แวร์ / การตลาดและคอนเทนต์ / บัญชีและการเงิน) แต่ละประเภทได้คอลัมน์บอร์ดตั้งต้นของตัวเอง และทุกโปรเจคตั้งคอลัมน์เองได้ในแท็บ "ตั้งค่า" (เพิ่ม เปลี่ยนชื่อ เรียง ลบพร้อมย้ายงาน) ทีมมี 4 บทบาท เจ้าของ / ผู้ดูแล / สมาชิก / ดูอย่างเดียว เปลี่ยนบทบาทได้ในหน้าเดียวกัน โปรเจคเดิมทั้งหมดกลายเป็นประเภท "ทั่วไป" งานอยู่คอลัมน์เดิม ลำดับเดิม และเวลาแก้ไขล่าสุดไม่เปลี่ยน เครื่องมือเฉพาะของแต่ละประเภท (รอบงาน เลขงาน ปฏิทินคอนเทนต์ เอกสารเงิน) มาในเฟส P1–P3

## 4. ความต้องการของระบบและการติดตั้ง

ไม่มี dependency หรือตัวแปรสภาพแวดล้อมใหม่ ใช้ PHP 8 / MariaDB 11.4 เดิม และ Sortable ที่มีอยู่

## 5. การรันและการนำขึ้นระบบ (deploy)

1. สำรองฐานข้อมูลก่อน (migration 038 แตะตารางงานโปรเจคที่มีข้อมูลจริง) — งานของเจ้าของ *ยังไม่ได้รันบน production*
2. วางโค้ดแล้วรัน `php scripts/migrate.php` (ใช้ 038) *รันแล้วบนฐานทดสอบ*
3. ถ้าเคยถอยโค้ดหลัง migrate แล้วกลับมาโค้ดใหม่ ให้รัน `php scripts/migrate.php --force` **ทันทีหลังวางโค้ดใหม่ ก่อนมีคนใช้** โปรเจค/งานที่โค้ดเก่าสร้างระหว่างนั้นได้คอลัมน์ครบ และงานที่ถูกย้ายระหว่างนั้นไปอยู่คอลัมน์ตาม status ที่โค้ดเก่าเขียน *รันแล้วบนฐานทดสอบ และมี test ครอบ*
4. snapshot ของบัญชีตัวอย่างที่ถ่ายก่อน 038 กู้คืนได้ (โปรเจคได้คอลัมน์ตั้งต้นตามประเภท) ไม่ต้องถ่ายใหม่ *รันแล้วผ่าน scripts/demo-reset.php*
5. เช็กว่าขึ้นแล้ว: เปิดเมนูโปรเจค เห็นแถบสีและชื่อประเภทในทุกแถว เปิดบอร์ดแล้วคอลัมน์ตรงกับของเดิม

## 6. คู่มือการใช้งาน

- **สร้างโปรเจค:** โปรเจค > สร้างโปรเจค > เลือกการ์ดประเภท > ถัดไป > ตั้งชื่อ > สร้างโปรเจค บอร์ดเปิดพร้อมคอลัมน์ของประเภทนั้น
- **ตั้งคอลัมน์ (เจ้าของ/ผู้ดูแล):** เปิดโปรเจค > แท็บ ตั้งค่า > คอลัมน์ แก้ชื่อในช่องแล้วออกจากช่องเพื่อบันทึก ลาก ⠿ เพื่อเรียงในกลุ่ม "เพิ่มคอลัมน์ในกลุ่มนี้" เพื่อเพิ่ม ลบคอลัมน์ที่มีงานจะถามว่าให้งานไปคอลัมน์ไหน
- **ทีม:** ตั้งค่า > ทีมและสิทธิ์ เชิญด้วยชื่อผู้ใช้หรืออีเมล เปลี่ยนบทบาทจากเมนูของแต่ละคน เอาออกจะบอกว่างานกี่งานจะไม่มีผู้รับผิดชอบ
- **เปลี่ยนประเภท (เจ้าของ):** ตั้งค่า > ประเภท > เลือกประเภทใหม่ > ยืนยัน คอลัมน์และงานไม่เปลี่ยน

| ข้อความ | แปลว่า | แก้ยังไง |
| --- | --- | --- |
| แต่ละกลุ่มต้องมีอย่างน้อย 1 คอลัมน์ | กำลังลบ/ย้ายคอลัมน์สุดท้ายของกลุ่ม | เพิ่มคอลัมน์อื่นในกลุ่มนั้นก่อน |
| มีชื่อคอลัมน์นี้อยู่แล้ว | ชื่อซ้ำในโปรเจคเดียวกัน | ใช้ชื่ออื่น |
| เพิ่มคอลัมน์ได้สูงสุด 12 คอลัมน์ต่อโปรเจค | ครบ 12 แล้ว | ลบคอลัมน์ที่ไม่ใช้ |
| เฉพาะเจ้าของโครงการเท่านั้นที่ตั้งผู้ดูแลได้ | ผู้ดูแลพยายามตั้งผู้ดูแล | ให้เจ้าของทำ |

## 7. โครงสร้างระบบสำหรับผู้ดูแล

```
บอร์ด / ตั้งค่า (projects-board.js, projects-team.js)
   │  column_id
   ▼
ProjectTaskController / ProjectColumnController ── requireRole() (ProjectAccess) ──► 403
   │
   ▼
ProjectTask::moveTo / reorder / moveColumnTasks / syncProjectShadow
   │   เขียน column_id + status เงา ผ่าน shadowStatusSql() ที่เดียว
   ▼
project_tasks.column_id ──FK SET NULL──► project_columns (project_id, name, grp, position)
```

- `models/ProjectColumn.php` — คอลัมน์ตั้งต้นตามประเภท แปลง status เดิมเป็นคอลัมน์ (client เก่า เช่น ติ๊กเสร็จบนแดชบอร์ด)
- `models/ProjectTask.php` — ทางเดียวที่ย้ายงานและเขียน status
- `controllers/ProjectColumnController.php` — API คอลัมน์ 4 ตัว
- `controllers/ProjectAccess.php` — `requireRole` ลำดับ owner 4 / Admin 3 / Editor 2 / Viewer 1 / อื่น 0
- `controllers/ProjectTeamController.php` — เชิญ เปลี่ยนบทบาท เอาออก
- `scripts/replay-migration.mjs`, `scripts/project-snapshot.php` — พิสูจน์ migration บนสำเนาฐานข้อมูล

**schema ที่เปลี่ยน (038):** `projects.type`, ตาราง `project_columns`, `project_tasks.column_id` (FK `ON DELETE SET NULL` เพราะลบโปรเจคแล้ว cascade สองทาง)

**จุดที่ต้องระวังเวลาแก้ต่อ**
- `project_tasks.status` เป็น **เงา** ของคอลัมน์ ห้ามเขียนตรง ๆ ใช้ `ProjectTask::moveTo`/`reorder` เท่านั้น กฎ: done → Done, todo → To Do, doing คอลัมน์สุดท้าย → Review, doing อื่น → In Progress ผู้อ่านเดิม (แดชบอร์ด นับความคืบหน้า) ยังพึ่ง `status = 'Done'` ได้
- บทบาทในฐานข้อมูล `Admin`/`Editor`/`Viewer` แสดงเป็น ผู้ดูแล/สมาชิก/ดูอย่างเดียว ลิงก์แชร์ใช้ `SHARE_ROLES` (เป็นผู้ดูแลไม่ได้)
- endpoint ใหม่ต้องใช้ `requireRole` ตัวเดียว และตอบ 404 เดียวกันสำหรับ id ที่ไม่มี/ของคนอื่น

## B6. คู่มือการใช้งาน

- **มุมมอง:** แท็บ รายการ กดหัวคอลัมน์เพื่อเรียง เลือก "จัดกลุ่มตาม" ได้ (คอลัมน์ / ผู้รับผิดชอบ / ความสำคัญ / ไม่จัดกลุ่ม) แท็บ ปฏิทิน เลื่อนเดือนได้ งานที่ไม่มีวันส่งอยู่ในกล่อง "ยังไม่ลงวัน" แถบกรองเหนือแท็บใช้ได้ทั้งสามมุมมอง กด "ล้างตัวกรอง" เพื่อกลับ
- **รายละเอียดงาน:** คลิกการ์ดหรือแถว แผงเปิดด้านขวา (มือถือเต็มจอ) ปุ่มคัดลอกลิงก์ให้ลิงก์ `?task=` ส่งให้เพื่อนในทีม
- **ความเห็น:** พิมพ์ `@` เพื่อเลือกคนในทีม Ctrl+Enter ส่ง ลบได้เฉพาะของตัวเอง (ผู้ดูแลขึ้นไปลบได้ทุกอัน) ผู้ดูอย่างเดียวอ่านได้อย่างเดียว
- **ไฟล์แนบ:** "แนบจากเครื่อง" เก็บลงโฟลเดอร์ "ไฟล์แนบ · <ชื่อโปรเจค>" ในคลังของคุณ หรือ "เลือกจากคลังไฟล์" สูงสุด 20 ไฟล์ต่องาน ถอดออกแล้วไฟล์ยังอยู่ในคลัง ถ้าลบไฟล์ในเมนูไฟล์ ไฟล์แนบหายตาม (มีกล่องเตือนบอกจำนวนงาน)
- **ช่องข้อมูลเพิ่มเติม (เจ้าของ/ผู้ดูแล):** ตั้งค่า > ช่องข้อมูล เพิ่มได้ 10 ช่อง ชนิด ข้อความ ตัวเลข วันที่ ตัวเลือก (≤20 ตัวเลือก) คน ติ๊ก
- **กระดิ่ง:** จุดแดงบอกจำนวนที่ยังไม่อ่าน คลิกรายการเพื่อไปที่งาน "อ่านทั้งหมด" เคลียร์ตัวเลข

| ข้อความ | แปลว่า | แก้ยังไง |
| --- | --- | --- |
| แนบได้สูงสุด 20 ไฟล์ต่องาน | ครบ 20 แล้ว | ถอดไฟล์ที่ไม่ใช้ |
| เพิ่มช่องข้อมูลได้สูงสุด 10 ช่องต่อโปรเจค | ครบ 10 แล้ว | ลบช่องที่ไม่ใช้ |
| มีชื่อช่องนี้อยู่แล้ว | ชื่อซ้ำในโปรเจค (เทียบวรรณยุกต์ด้วย) | ใช้ชื่ออื่น |
| ค่าในช่อง <ชื่อช่อง> ไม่ถูกต้อง | ค่าไม่ตรงชนิด เช่น ตัวเลือกที่ไม่มี คนนอกโปรเจค | เลือกค่าใหม่ |

```
กระดิ่ง (notifications.js) ─► NotificationController ─► notifications (ตารางกลางทั้งแอป)
```

- `models/Notification.php` — `send()` ทางเดียวที่สร้างการแจ้งเตือน: ข้ามผู้รับที่เป็นคนทำ → INSERT → Telegram → ปลุก Push ช่องทางนอกแอปล้มไม่ทำให้คำขอล้ม
- `controllers/ProjectAttachmentController.php` — ทางเดียวที่คนอื่นเปิดไฟล์ส่วนตัวได้ ลำดับตรวจ: งานมองเห็นได้ (ไม่เจอ = 404 เดียวกัน) → ไม่ใช่แขก → ไฟล์ผูกกับงานนี้ → บทบาท
- `models/ProjectField.php` — ทุกการเขียนอยู่ใน `ProjectColumn::locked()` ตรวจค่าตามชนิดใน `cleanValue`
- **schema 039:** `project_tasks.description`, `project_activities.task_id` (FK SET NULL), `project_task_comments`, `project_task_files` (FK CASCADE ทั้งงานและไฟล์), `notifications`
- **schema 040:** `project_fields`, `project_tasks.custom` (TEXT เก็บ JSON `{"<field_id>": ค่า}`)
- **schema 041:** `project_activities.private` (0/1) บรรทัดเก่าทั้งหมดเป็น 0

**จุดที่ต้องระวังเวลาแก้ต่อ**
- ค่าช่องข้อมูลเขียนด้วย `JSON_MERGE_PATCH` เฉพาะ key ที่เปลี่ยน (null = ลบ key) ห้ามเขียนทับทั้งก้อน ไม่งั้นสองคนแก้คนละช่องจะทับกัน
- controller ตรวจเฉพาะค่าที่ต่างจากค่าเดิม (`$touched`) เพราะฟอร์มส่งค่าทุกช่องกลับมา ค่าเก่าที่ไม่ผ่านกฎแล้ว (คนออกจากทีม) จะทำให้บันทึกงานไม่ได้
- `apiFetch` ไม่แปลง body เป็น JSON ให้ ต้อง `JSON.stringify` เอง · `Request::input()` ทิ้งค่าที่เป็น array ใช้ `Request::list()` · `ProjectColumnException` อยู่ในไฟล์ `ProjectColumn.php` model อื่นต้อง `require_once`
- endpoint ใหม่ที่คืนข้อมูลงานต้องคิดเรื่องแขกลิงก์แชร์ (D-5) ทุกครั้ง บรรทัดกิจกรรมที่มีชื่อไฟล์แนบ ชื่อหรือค่าช่องข้อมูล ต้องส่ง `private = true` ให้ `ProjectActivity::log()` ค่าช่องลงเป็นบรรทัดแยกจากการแก้งานปกติด้วยเหตุนี้
- จำนวนไฟล์แนบต่องานตัดสินใน `ProjectAttachment::linkIfRoom()` (lock ของโปรเจค) `assertRoom` ใน controller เป็นแค่การตอบเร็วก่อนอัปโหลด

## B9. ข้อจำกัด ความเสี่ยง และหนี้เทคนิค

- บัญชีทดลอง (demo) แนบไฟล์ไม่ได้ เพราะไฟล์แนบเก็บลงคลังไฟล์ ซึ่งบัญชีทดลองเขียนไม่ได้เหมือนหน้าคลังไฟล์
- คนแนบลบไฟล์ในคลังของตัวเอง ไฟล์แนบหายจากงานด้วย (D-4 ยอมรับข้อนี้ มีกล่องเตือน) ส่วนคนแนบที่ออกจากโปรเจค ไฟล์แนบยังเปิดได้
- ไฟล์ใน Drive ของคนแนบเปิดได้ตราบที่ token Drive ของเขายังใช้ได้ ถ้าเขาตัดการเชื่อม Drive ไฟล์แนบนั้นเปิดไม่ได้
- มือถือ: ถ้ามีช่องข้อมูลที่กรองได้หลายช่อง แถบกรองสูงหลายบรรทัด
- แถวในรายการยังไม่มีไอคอนนับความเห็น/ไฟล์แนบ (ต้อง query เพิ่ม และต้องซ่อนจากแขก)
- ผู้ตรวจอิสระ (Opus, เห็นแค่สเปกกับ diff):
  - รอบ 1 **ไม่ผ่าน** 5 ข้อ ผมรันซ้ำแล้วเกิดจริงทุกข้อ: แขกลิงก์แชร์เห็นชื่อไฟล์แนบและค่าช่องข้อมูลผ่านฟีดกิจกรรม/ประวัติ (สูง), แนบพร้อมกันได้ 21 ไฟล์, ชื่อ/ตัวเลือกช่องเป็น list กลายเป็น "Array", เปิดงานที่มีความเห็นเกิน 200 ไม่เห็นล่าสุด, ลบโฟลเดอร์ไฟล์แนบไม่เตือน — แก้ด้วย migration 041 (CR-2), `linkIfRoom` ใน lock, ตรวจชนิด, 200 ล่าสุดตอนเปิดแผง, นับโฟลเดอร์ซ้อนด้วย recursive CTE
  - รอบ 2 **ไม่ผ่าน** การแก้รอบ 1 ปิดได้ทุกข้อ แต่เจอใหม่: ลิงก์แชร์แบบแก้ไขได้ (Editor) ส่ง `custom` แล้วได้ชื่อช่องจากข้อความ error เดาค่าและเขียนทับค่าได้ (บล็อก), แผงที่แก้แค่ค่าช่องได้บรรทัดกิจกรรมเปล่าเพิ่ม (`FOUND_ROWS` ทำให้ update คืน true เสมอ), ค่าข้อความ 500 ตัวทำให้ 500 เพราะ `action` ยาว 255, polling ข้ามความเห็นเมื่อมาเกิน 200 ระหว่างรอบ — แก้ทั้งหมด: แขกส่ง `custom` ได้ 403 ข้อความเดียว, ลงเฉพาะบรรทัดลับเมื่อเปลี่ยนแค่ค่าช่อง, `log()` ตัดที่ 255 และค่าช่องแสดง 60 ตัว, polling เรียงเก่าไปใหม่, การลบหลายรายการในคลังไฟล์เตือนด้วย
  - รอบ 3 (โจมตีเฉพาะลิงก์แชร์ทั้ง Viewer และ Editor ทุก route) **ไม่พบทางรั่ว**ของความเห็น ไฟล์แนบ ชื่อช่อง หรือค่าช่อง แต่ตัดสินไม่ผ่านเพราะแขก Editor มอบหมายงานให้คนในทีมได้ 500 หลังบันทึกไปแล้ว (`notifications.actor_id` มี FK ไป users แต่แขกมี id 0) และแขกนับจำนวนช่องได้จาก 403/404 — แก้: `Notification::send` เก็บผู้กระทำที่ไม่ใช่ผู้ใช้เป็น null (คนรับงานได้แจ้งเตือน), แขกได้ 404 เดียวกันทุก id ช่อง ทั้งสองข้อมี test ที่แดงบนโค้ดเก่าแล้วเขียว ไม่ได้ส่งผู้ตรวจรอบ 4
  - ผู้ตรวจรอบ 3 เจอของเดิมก่อน P0b (ไม่นับ): `GET /api/projects/{id}/members` คืนอีเมลสมาชิกให้แขกลิงก์แชร์, ชื่องานเกิน 255 ตัวได้ 500
- ข้อที่ผู้ตรวจสงสัยแต่ยังไม่พิสูจน์: ถ้างานถูกลบพอดีระหว่างแนบไฟล์ `INSERT IGNORE` อาจกลืน FK error แล้วตอบ 201 (ไฟล์ยังอยู่ในคลัง ไม่ได้ผูกกับงานไหน)
- กดบันทึกงานโดยไม่เปลี่ยนอะไรเลย ยังลงบรรทัด "อัปเดตงานย่อย" เปล่าในฟีด (ของเดิมก่อน P0b: ฐานข้อมูลตั้ง `FOUND_ROWS` ทำให้ update คืน true เสมอ)
- งานที่ไม่มีความเห็นตอนเปิดแผง แล้วมีความเห็นใหม่เกิน 200 รายการภายใน 30 วินาที รอบดึงถัดไปได้ 200 รายการล่าสุด รายการแรก ๆ จะเห็นเมื่อเปิดแผงใหม่ (เซิร์ฟเวอร์แยก `after=0` ของการเปิดแผงกับการดึงซ้ำไม่ได้)
- แถวกิจกรรมที่เขียนก่อน 041 เป็นไม่ลับทั้งหมด (ไม่มี backfill) มีผลแค่ฐานทดสอบ เพราะ P0b ยังไม่ deploy

## 1. เสร็จคืออะไร (ตรวจได้)

1. แท็บ บอร์ด · รายการ · ปฏิทิน · ภาพรวม · ตั้งค่า แสดงงานชุดเดียวกัน ตัวกรองค้างเมื่อสลับแท็บ รายการเรียง/กรอง/จัดกลุ่มได้ ปฏิทินมี "ยังไม่ลงวัน" (REQ-P4)
2. คลิกงานจากทุกมุมมองเปิดแผงรายละเอียด (แบบ A) มีช่องข้อมูล คำอธิบาย เช็กลิสต์ ไฟล์แนบ ความเห็น ประวัติ ความเห็นใหม่ของคนอื่นขึ้นเองภายใน 1 นาที ลิงก์ `?task=<id>` เปิดงานตรงได้ (REQ-P5)
3. ไฟล์แนบอัปโหลดหรือเลือกจากคลังไฟล์ได้ ทุกคนในโปรเจคดาวน์โหลดได้ (รวมไฟล์ใน Google Drive ของคนแนบ) คนนอกโปรเจคได้ 404 (REQ-P5, EDGE-P4)
4. กระดิ่งที่แถบบนทุกหน้า: ถูกมอบหมายงาน, ถูกกล่าวถึง @ ในความเห็นหรือแชท, คนออกจากทีม ไม่แจ้งเรื่องที่ตัวเองทำ ส่งต่อ Push/Telegram ตามที่ผู้ใช้เปิดไว้ (REQ-P10)
5. ช่องข้อมูลเพิ่มเติม 6 ชนิด กรอกในแผงรายละเอียด กรอง/เรียงในรายการได้ (REQ-P6 ทำหลังข้อ 1–4)
6. ลิงก์แชร์ยังอ่านอย่างเดียว และข้อมูลใหม่ (ความเห็น ไฟล์แนบ ช่องข้อมูล) ออกไปทางลิงก์แชร์ตามคำตอบ D-5 เท่านั้น (REQ-P11)
7. test ชุดเต็ม, e2e 3 ขนาดจอ, PHPStan, check-css ผ่าน, ตรวจอิสระก่อนจบ

## 3. ร่างแบบ: ไฟล์แนบ (D-4)

### แบบ A: ไฟล์แนบ = ลิงก์ไปที่ไฟล์ในคลังของคนแนบ (แนะนำ)
- ตาราง `project_task_files(task_id, file_id, added_by, created_at)` ไฟล์ที่อัปโหลดจากงานลงคลังของคนแนบในโฟลเดอร์ "ไฟล์แนบ · <ชื่อโปรเจค>" (สร้างให้เอง) "เลือกจากคลังไฟล์" คือผูกไฟล์ที่มีอยู่แล้ว
- ดาวน์โหลด `GET /api/projects/tasks/{tid}/files/{fid}`: ตรวจว่าเป็นคนในโปรเจค + ไฟล์ผูกกับงานนี้ แล้ว `FileStore::send()` ของเดิม ทางเดียว ไม่เปิด `/api/files/{id}/download` ให้คนอื่น
- ข้อดี: ใช้ที่เก็บ โควตา และ Google Drive เดิมทั้งหมด ไม่ต้องมีที่เก็บใหม่ โค้ดน้อย
- ข้อเสีย: คนแนบลบไฟล์ในเมนูไฟล์ของตัวเอง ไฟล์แนบหายด้วย (FK CASCADE) → หน้าลบไฟล์เตือน "ไฟล์นี้แนบอยู่ในงาน N งาน" ส่วนคนแนบออกจากโปรเจค ไฟล์แนบยังอยู่ (ยังเป็นไฟล์ของเขา)

### แบบ B: โปรเจคมีที่เก็บของตัวเอง
- ตาราง `project_files` + โฟลเดอร์ `uploads/projects/<id>/` แยกจากคลังส่วนตัว
- ข้อดี: ไฟล์อยู่กับโปรเจคแม้คนแนบลบบัญชี
- ข้อเสีย: ต้องทำที่เก็บ โควตา และการเชื่อม Google Drive ซ้ำอีกชุด ("รวม Google Drive ถ้าเปิดไว้" ใน REQ-M5 ทำยาก เพราะ Drive เป็นของคน ไม่ใช่ของโปรเจค) ลบโปรเจคต้องลบไฟล์บนดิสก์เอง

**คำแนะนำ: A** ตรงกับ "ใช้ที่เก็บไฟล์ของ DayFlow" ในสเปกโดยตรง และได้ Drive มาฟรี

## 4. ร่างแบบ: ค่าของช่องข้อมูลเพิ่มเติม (D-6)

ทั้งสองแบบมี `project_fields(id, project_id, name, kind ENUM('text','number','date','select','person','check'), options JSON, position)`

### แบบ A: เก็บค่าเป็น JSON ในแถวงาน (แนะนำ)
- `project_tasks.custom JSON` เช่น `{"12": "เว็บ", "13": 6}` กรอง/เรียงทำในเบราว์เซอร์ (บอร์ดโหลดงานทั้งโปรเจคอยู่แล้ว สเปกกำหนด ≤500 งานต่อบอร์ด)
- ลบช่อง: `JSON_REMOVE` ทุกงานของโปรเจคใน UPDATE เดียว (`updated_at = updated_at`)
- ข้อดี: ไม่มี JOIN ไม่มีตารางใหม่ต่อค่า โหลดงานยังเป็น query เดียว
- ข้อเสีย: กรองด้วย SQL ฝั่งเซิร์ฟเวอร์ยาก (ยังไม่มีที่ต้องใช้)

### แบบ B: ตารางค่าแยก `project_task_values(task_id, field_id, value)`
- ข้อดี: กรองด้วย SQL ได้ ลบช่องแล้วค่าหายตาม FK
- ข้อเสีย: โหลดงานต้อง JOIN หรือ query เพิ่ม ทุกการบันทึกงานเขียนหลายแถว

**คำแนะนำ: A** การกรองทั้งหมดทำในเบราว์เซอร์อยู่แล้ว (REQ-P4) และย้ายเป็นแบบ B ภายหลังได้ด้วย migration เดียวถ้าวันหนึ่งต้องกรองฝั่งเซิร์ฟเวอร์

## 5. แบบที่เหลือ (ตัดสินเอง ย้อนได้)

- **แจ้งเตือน** ตารางเดียวทั้งแอป `notifications(id, user_id, actor_id, kind, title, body, url, read_at, created_at)` ไม่ผูกกับโปรเจค เมนูอื่นใช้ต่อได้ สร้างผ่าน `Notification::send($toUser, $kind, ...)` ที่เดียว ซึ่ง (1) ข้ามถ้าผู้รับคือคนทำ (2) INSERT (3) Telegram ตามเหตุการณ์ที่เปิด (4) ปลุก Push เก็บ 30 วัน (cron ลบ) กระดิ่งดึงจำนวนที่ยังไม่อ่านทุก 60 วินาทีเฉพาะตอนแท็บเปิดอยู่
- **ความเห็น** `project_task_comments(id, task_id, user_id, body, created_at)` ลบได้โดยคนเขียนหรือผู้ดูแลขึ้นไป แผงที่เปิดอยู่ดึงความเห็นใหม่ทุก 30 วินาที (`?after=<id>`) จึงไม่เกิน 1 นาที
- **@กล่าวถึง** ช่องพิมพ์แทรก `@username` (username ไม่ซ้ำ) เซิร์ฟเวอร์หาเฉพาะคนในโปรเจคจากข้อความ แสดงผลเป็นชื่อที่แสดง ใช้ทั้งความเห็นและแชท
- **มอบหมายงาน** เปลี่ยนผู้รับผิดชอบเป็นคนอื่น → แจ้งคนนั้น
- **ประวัติของงาน** `project_activities.task_id` (NULL สำหรับของเดิม) ทุก log ที่เกี่ยวกับงานใส่ id
- **มุมมอง** รายการ/ปฏิทินวาดในเบราว์เซอร์จากข้อมูลชุดเดียวกับบอร์ด (ไม่มี API ใหม่) ตัวกรองเก็บใน `sessionStorage` ต่อโปรเจค ค้างเมื่อสลับแท็บและรีเฟรช
- **แผงรายละเอียด** แทนหน้าต่างแก้งานเดิม URL `?task=<id>` z-index อยู่เหนือแถบแท็บล่างของมือถือ (เจอตอนทำ mockup)
- **ภาพรวม** ย้ายวิดเจ็ตเดิมจากใต้บอร์ดเข้าแท็บ ไม่เปลี่ยนเนื้อหา

## 8. สมมติฐาน (ตัดสินเอง ย้อนได้ ทักได้)

- ความเห็นลบได้โดยคนเขียนหรือผู้ดูแลขึ้นไป ยังไม่มีการแก้ไขความเห็น
- แจ้งเตือนในแอปเก็บ 30 วัน กระดิ่งตรวจทุก 60 วินาทีเมื่อแท็บเปิดอยู่
- ช่องข้อมูลเพิ่มเติมสูงสุด 10 ช่องต่อโปรเจค ช่อง "ตัวเลือก" มีได้ 20 ตัวเลือก
- ไฟล์แนบต่องานสูงสุด 20 ไฟล์ ขนาดตามขีดจำกัดการอัปโหลดเดิมของเมนูไฟล์
